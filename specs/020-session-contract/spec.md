## Overview

A recording made by this engine depends on five things besides the sound that reached the microphone: the library and its model versions, the host rate, the settings, the seed and the recording counter (the microphone hiss is a deterministic stream keyed by the seed and the counter), plus what happened during the recording: the values that changed through the schedule, the moments the voice activation removed, and how the recording ended. The engine already reports the changes and the gaps to the host, call by call, and already exports the recording as a stored form; it does not yet say, in one versioned document, how a given recording was made. This feature adds that document, the **processing record**, written beside the stored form and never inside it: a text form a person can read, a reader that validates it and reports its contents, a digest that ties the record to its recording, a way to construct an engine at a given recording counter, and three timeline maps so an app can place a change or a gap on the microphone's own clock. With the kept microphone audio (the product's decision O-3), a recipient can re-render the recording from the record and compare digests. The feature changes no audio.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Write the record and re-render the recording (Priority: P1)

An app finishes a recording, writes its processing record beside the exported stored form, and later (or on another machine with the same library) re-renders the recording from the kept microphone audio and the record, and finds the digests equal.

**Why this priority**: it is the contract itself; the maps and the reports serve it.

**Independent Test**: at each host rate, record a stimulus with two scheduled record-side changes and a voice-activation pause, write the record, construct a second engine from the record's identity and configuration (at the record's counter, its memory filled to the record's remaining capacity), feed the same input with the record's entries scheduled, stop at the record's stop position, export, digest: equal to the record's; then make each named effective change and the digest differs; change a playback-side setting and it does not.

**Acceptance Scenarios**:

1. **Given** a finished recording and the host's collected events, entries and stop report, **When** the record is written, **Then** it is a valid form of D2 whose identity, configuration and run parts carry the values of D1 from the slot's block (the configuration as it was at the start, even after a `reconfigure` or a landed change since), its digest equals the digest of the recording's exported bytes, its event positions carry map (b)'s host-input positions, and writing it again gives the same bytes.
2. **Given** a record and the kept microphone audio, **When** a second engine is built per D6 and records the audio with the record's entries scheduled and the same stop, **Then** its stored form's digest equals the record's, at all seven host rates, with the codec on and bypassed, with and without record-side changes, with the voice activation in drop and in mute mode, for a host stop and for the memory-full self-stop (the re-render engine's memory filled to the record's remaining capacity).
3. **Given** the same re-render with one effective change (FR-005's list), **When** it is digested, **Then** the digest differs; **Given** a playback-side setting or live control changed instead, **Then** the digest is unmoved.
4. **Given** a record, **When** it is read back and written again, **Then** the bytes are identical (the round trip), and the read-out reports every field of D1.
5. **Given** an engine that recorded c times (with a landed record-side change, a pause at the end of the last recording, a burst in its last 100 ms and a one-pass run between), **When** it records once more, **Then** that recording is bit-identical to the first recording of a fresh engine built at counter c with the same settings and seed; the fresh engine's one-pass is bit-identical to the original's next one-pass; and `recording_counter()` reads c before and c + 1 after.

### User Story 2 - Read any record honestly (Priority: P2)

An app or a recipient reads a record written by another engine version or for another recording and learns what is still true and what differs.

**Independent Test**: a doctored set of records: an unknown form version, a malformed line, a missing field, a bad checksum (each refused with its status); a different library version, a different stage model version, a different host rate, an unknown setting name, a digest that does not match the named recording, a run shorter than its totals (each read with the difference reported); the status and the flags shown by tests.

**Acceptance Scenarios**:

1. **Given** a record whose form version is unknown, or whose checksum does not match, or with a malformed or missing line, **When** read, **Then** the reader refuses it with the status naming the reason and reads nothing else; a form version older than this library's is read.
2. **Given** a record from a library or a stage model version different from the reader's, or naming a setting the reader does not know, **When** read, **Then** the read-out carries the record's versions and a flag per difference (the unknown names listed); nothing is refused.
3. **Given** a record and a recording in the engine's memory, **When** the digest is checked against that recording, **Then** the read-out says whether they agree.
4. **Given** a recording that was imported, **When** its record is written, **Then** the record names its origin as imported, carries only the stored form's identity and the digest, and the read-out reports the re-render contract unavailable.
5. **Given** a run with fewer events or entries than the slot's totals, **When** the record is read, **Then** the read-out flags the run incomplete with both counts; **Given** an inconsistent run, **When** the record is written, **Then** the writer refuses it with its status.

---

### User Story 3 - Place a moment on the microphone's timeline (Priority: P3)

An Investigation-mode app shows a logged change or a voice-activation gap on the recording's review timeline at the moment of the microphone audio it belongs to, and shows which input moment a stored sample aligns with.

**Independent Test**: at each host rate, a stimulus of short distinct bursts at known host-input positions inside kept regions, with silence between them that opens gaps: each burst's onset is located in the kept stream; map (a) of that kept index contains the burst's host-input onset and map (b) of the onset returns that kept index, within one device sample (±2 with the codec on); the splice arithmetic equals the VAS-bypassed run's indices bit for bit; map (c) equals the speed stage's trace.

**Acceptance Scenarios**:

1. **Given** a record with voice-activation events, **When** a kept sample is mapped by (a), **Then** its alignment contains the burst onset it came from, within one device sample across every gap, and its window is the direct-path window of D8; the recording's ends are clamped and reported.
2. **Given** a host-input position, **When** mapped by (b), **Then** the result is the kept sample it reaches or the event that removed it, and mapping that kept sample back contains the position; the one-pass's output-to-input map agrees with its events.
3. **Given** a speed schedule with a request on the first output, one landing on a fade's last output, a waiting request equal to the active level, a level-3 request during a wait, a request at the latch and two requests inside one fade, **When** an output index is mapped by (c), **Then** the place equals the speed stage's trace at that output, at every rate.

### Edge Cases

- A slot that holds no recording: the writer refuses it with the existing status.
- A record requested while a recording is in progress: refused (the stop's report is part of the run); the engine's state statuses apply.
- An imported recording (no block): `origin = imported`, identity only (US2 AS4).
- A host that collected no events or entries (empty buffers) for a run with non-zero totals: a valid record flagged incomplete; the re-render from it fails the digest.
- Entries from another stream, or out of order, or past the stop: refused as an inconsistent run (D10).
- A record naming a setting this engine does not know: reported; lacking a required field: refused.
- A stop moved by less than one frame's worth of input, or an input change inside a removed gap: the digest may be unmoved; the record's own fields move and the reader reports the difference between two records.
- The counter at construction near its maximum: it wraps as today's counter does.
- The maps near the recording's ends: the first kept samples align with inputs before the recording's start (the latency) and the last with the stop's silence (the flush, then the padding, which the record's padding start separates); the alignment is clamped to the recording's input range and the clamping reported.
- `erase` moves the blocks with the recordings; `reconfigure` with the memory kept keeps the blocks; with the memory emptied, none remain.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The engine MUST write, for a finished recording in its memory, a processing record in the form of D2 with the parts of D1, from the slot's block (the counter, the settings, the seed, the host rate, the remaining capacity, the totals), the engine's identity (library and stage model versions), the digest of the recording's exported bytes, and the events, entries and stop report the host collected, computing each event's host-input position through map (b); the same inputs MUST give the same bytes on every platform; a length-then-write pair, outside the processing path; an inconsistent run MUST be refused with its own status.
- **FR-002**: The engine MUST read a processing record into a structured read-out, refusing an unknown (newer) form version, a malformed line, a missing required field or a checksum mismatch with a distinct status each, reading every earlier form version, and reporting (not refusing) a library version, a stage model version, a host rate, an unknown setting name, an incomplete run or a digest that differs from this engine's or from a named recording's; reading then writing a valid record MUST give identical bytes.
- **FR-003**: The engine MUST offer the 64-bit FNV-1a digest of D3 on any byte sequence and on a recording in its memory, computed without allocation; the record's checksum line MUST use the same function.
- **FR-004**: The engine MUST be constructible at a given recording counter per D5 (the next recording's and the one-pass's hiss streams keyed to it; the counter's rules unchanged) and MUST keep the per-slot block of D5 at `start_recording`, moved by erase, absent for an imported recording.
- **FR-005**: Re-rendering per D6 MUST reproduce the stored form's digest in every cell of the matrix (seven rates × codec on/bypassed × with/without record-side changes × drop/mute × host stop/self-stop). Each of these effective changes MUST change the digest: the seed; the counter; one record-side setting per modeled record stage (`mic.hiss_offset_db`, `agc.knee_dbfs`, `vas.threshold_dbfs`, `speech_codec_enabled`) and the memory's capacity in the self-stop cell; a 10 ms burst at −20 dBFS inserted at a kept input position; an effective entry moved by one device sample or its value by its manifest step; the host's stop moved earlier by one frame's worth of input (120 · rate ÷ 6000 host samples). A change of any playback-side setting or live control MUST leave the digest unmoved.
- **FR-006**: The maps of D8 MUST be pure functions of their stated inputs (a and b: the record's events, the host rate, the latency and the stop fields; c: the app's playback entries, the unit count, the start level and the host rate), with the splice arithmetic bit-exact against the VAS-bypassed run, the alignment within one device sample of a burst's onset (±2 with the codec on) at all seven host rates, map (c) equal to the speed stage's trace on the six corner cases of US3 AS3, and the ends clamped and reported.
- **FR-007**: The change entry's reserved field MUST carry the stream word of the stream that applied it (set on the landing path); the stop report MUST carry the stop's input position and the padding start; every existing figure of specs 015 and 017 MUST be unchanged, and a mixed log's entries MUST be attributable to their stream.
- **FR-008**: No audio change: every golden file, SHA guard and smoke hash MUST be unmoved; the processing path MUST allocate nothing new (the blocks and the totals are reserved at construction and written at the recording's start, stop and landings) and its per-sample cost MUST be within 3 % of 0.19 (5 % on the runner).
- **FR-009**: The C API MUST expose the writer, the reader, the digest, the constructor, the maps and the feed-point helper, panic-safe, with no Rust types and a `struct_size` on each new struct; the Swift package MUST pass the parity tests and carry the re-render recipe; the header MUST be regenerated.
- **FR-010**: The records MUST be updated: the stage manifest's version line only, the control manifest unchanged, a "Processing record" section in the guide (the form, the contract, what the digest shows and does not show in D3's words, the maps and what leads what, the seed rule, the feed-point rule, the collection sizing from the events bound, the recipe), scanned with the per-feature forbidden list of the Clarifications; the CHANGELOG under Added (with the stream-word note for 0.16/0.17 callers); the product notes (controls-discussion § 2c and § 4 item 7, investigation-mode § 2 "Timeline mapping", § 4 and § 5, brief.md § 4 and the session bullets, decisions.md's free-tier row); specs 015 and 017's pointers to 020 resolved; version 0.20.0; no new assumption (the record is data about a recording, not a device behavior).

### Out of Scope

- The playback side's listening session and a record for the one-pass (D7).
- A state checkpoint and restore; an offline reader of the codec's frame parameters (both later, on an app request).
- Raw-audio storage, sensors, clocks and marks (the app's).
- Any change to the stored form (`RRDR60RC` v2 is unchanged and never carries the record).
- A cryptographic signature or a stronger hash (a later form version may add a line).
- A per-item length limit (none is modeled; it would be a new spec).

### Key Entities

- **Processing record**: the versioned text document of D1/D2 describing how one recording was made; written beside the stored form.
- **Slot block**: the fixed-size per-recording data of D5 the engine writes at `start_recording` (counter, settings, seed, host rate, remaining capacity, totals).
- **Run data**: the events, change entries and stop report the host collected from a recording's calls; input to the writer.
- **Stop position**: the host input samples the host fed before it called `stop_recording` (new in the stop report); `input_samples_total` = the stop position + the stop's fed silence (the latency flush and, with the codec on, the padding); the **padding start** is the kept index where the padding begins. A re-render feeds exactly the stop position's samples and calls the same stop; a self-stop occurs by itself when the memory's remaining capacity matches.
- **Digest**: the 64-bit value of D3 over a stored form's bytes; the tie between a record and a recording.
- **Timeline map**: the three pure functions of D8.

## Assumptions

- **Alternatives considered**: a binary record (D2; rejected: the point is a document a person and any tool can read; the stored form stays binary); C99 hex floats for the real numbers (the core has no hex-float printer or parser; decimal round-trip is exact in the core and in every correctly rounding parser); CRC-32 for the record's checksum (one function serves both lines); SHA-256 as the digest (about 150 lines, off the processing path; not chosen because the digest's purpose is consistency, a later line can add it); refusing on a model-version difference (D4; a record is still true about its recording; the product note asked for a refusal); a configuration generation per slot with a refusal after `reconfigure` (D5; a reconfigure would forfeit the record, which defeats case files); construct-at-counter as a setting (D5; the counter is state, and a setting would have to be ignored by `reconfigure`); the engine keeping each recording's run data (D10; unbounded memory for the voice-activation events of a 60-minute recording, against the allocation-free processing path); dropping the self-stop from the contract (D6; carrying the remaining capacity is one integer); including the playback side now (D7; the app already has spec 015's log, and a listening session has no stored form to digest); an independent walker for map (c) (D8; the shared automaton is bit-identical by construction and the speed and changes goldens guard the refactor; the walker is the plan's fallback if the refactor costs on the hot path); keeping the four live controls as context (D1; none touches a stored byte, and the rule "everything in the record enters the contract or describes the run" is cleaner).
- **The kept microphone audio is the samples fed to the engine** (the app quantizes at the feed point to 24 bits and stores losslessly, investigation-mode.md § 4; the engine's helper of D12 converts them); a re-render from any other audio is not covered.
- **The record is consistent, not signed**: anyone with the library can write a consistent record for any audio; the digest shows that a record and a recording belong together, not who made them.
- **The counter per slot** survives erase and renumbering with the recording it belongs to; import sets no block; export does not carry it (the stored form is unchanged).
- **Model versions are necessary, not sufficient**: the resampler, the narrowing, the hiss generator and the codec's arithmetic live under the library version, so the contract's condition is the library version (D4).
