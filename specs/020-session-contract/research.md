# Research: Processing Record (spec 020)

## R-01 The alignment, the direct-path window and the maps (D8 a, b)

**Decision.** The recorder's decimator emits device sample k on host push n_k = ⌊k · m ÷ l⌋ (the rate plan's l/m; the identity at 6 kHz) with a causal kernel centred D = `delay_host_samples()` host samples back, and stage 4 adds its 1 kHz group delay; the record path's latency to the encoder's input is L_pre = `latency_host_samples_pre_encoder()` (spec 006's rounded figure without the codec's 180 kept samples), published as `Pipeline::record_latency_pre_encoder_samples()` and recomputed by `timeline` from the settings (the rate plan plus stage 4's constant). The recorder's events are in device samples (`EventCounters::new(1, 1)`). So:

- (a) kept k ↔ host input centre **c(k) = ⌊(k + R(k)) · m ÷ l⌋ − L_pre**, R(k) = Σ{e.input_length : e.output_position ≤ k}; the direct-path window [c − D, c + D] (a convention: the decimator's kernel half-length; stage 4 is IIR); with the codec on, kept k in frame f = ⌊k ÷ 120⌋ is widened to the kept range [120f − 132, 120f + 179] (the coder's reach before a frame: max(the 132-sample past excitation, the 60 past input samples of the LPC window); after it: the frame and its 60-sample look-ahead; −22 … +30 ms re the frame start; corrected at implementation from a 240 the review found unjustified), converted by c(·). Below 0 the centre is clamped and `clamped` set (the first kept samples align with inputs before the recording's start); past the stop's input position (the flush and the padding) likewise.
- (b) host input p ↔ kept: j = `record_landing(p + L_pre, rate)` = ⌈(p + L_pre) · l ÷ m⌉ (the inverse pair is `record_landing` ↔ ⌊k·m/l⌋, not the playback upsampler's d(P)), then walk the events: with R_before the removed samples of the events before e, the removed region of e is [e.output_position + R_before, + e.input_length); j inside one → `Removed { event_index }`; otherwise kept k = j − R(j). Mute mode: nothing removed, the regions reported.
- The event line's `host_input_position` is c computed with the events strictly before e, at e.output_position: the first removed input sample.
- The one-pass map: output position o ↔ input o − `latency_samples()` + the removed host samples at or before o (the one-pass's events are in host units, the cumulative floor), clamped at 0 and reported.

**Oracles.** (i) the splice arithmetic bit-exact with the codec bypassed: drop-run stored sample k equals the VAS-bypassed run's stored sample k + R(k) bit for bit (the pre-gate streams are identical); (ii) the latency convention on an impulse through `record_only` at seven rates (one onset, no gate; the kept peak at c⁻¹(impulse) within one device sample); (iii) the markers: 10 ms bursts at −20 dBFS at known host positions inside kept regions with silence that opens gaps; each burst's onset located by **the same detector** in the drop-mode recording and in its VAS-bypassed, codec-bypassed twin; map (a) of the drop-mode kept index contains the burst's host onset and map (b) of the onset returns that kept index within one device sample (rate ÷ 6000 host samples), across every gap; with the codec on both recordings are decoded and cross-correlated (±2 device samples, spec 008's figure); a codec-on marker test that fails under `record_latency_samples()` (30 ms late) pins finding 1.

## R-02 Numbers, lines, the writer and the reader

**Decision.** `core::fmt::Display` for `f32`/`f64` is the shortest round-trip decimal and `str::parse` is correctly rounded, so a printed value parses to the same bits (hex floats have neither a printer nor a parser in core). The writer is pure: `record::write(readout: &RecordReadout, events: &[RecordEvent], changes: &[ChangeEntry], out: &mut [u8]) -> Result<usize>` formats into a `Sink { out, pos, overflow }` implementing `fmt::Write`; `record::len` runs it with a counting sink (exact; deterministic); the engine's `processing_record_write(number, run, out)` fills a `RecordReadout` from the slot block and the identity, computes each event's host position through R-01, and delegates. Lines are `name = value\n` (one space each side; names `[a-z0-9_.]+`; the event and change rows space-separated, named by the `event.fields` / `change.fields` lines); the record ends with exactly one LF; the checksum covers every byte above its line, the LF before it included. The reader walks once: line 1 `rr_dr60_processing_record_version = n` (n = 0 or n > `FORM_VERSION` → `UnknownRecordVersion`); the last line's checksum (`RecordChecksumMismatch`; a missing final LF is malformed); every line's shape and a name the version does not define (`MalformedRecord { line }`); the required fields per origin (`MissingRecordField`); unknown `setting.` names counted and listed through `record_unknown_setting`; a parsed NaN or infinity is malformed. Batch reads fill caller buffers (`record_events` into `&mut [VasEvent]`, `record_changes` into `&mut [ChangeEntry]`); the single-row cursors re-scan.

## R-03 FNV-1a 64

**Decision.** offset basis 0xcbf29ce484222325, prime 0x00000100000001b3; per byte: h ^= b; h = h.wrapping_mul(prime). Each step is a bijection on 2⁶⁴, so two equal-length inputs differing in one byte never collide; unrelated inputs coincide at 2⁻⁶⁴; deliberate collisions are easy (not a signature). Pinned by `""` → 0xcbf29ce484222325, `"a"` → 0xaf63dc4c8601ec8c, `"foobar"` → 0x85944171f73967e8. `recording_digest(number)` hashes a recording in memory in two passes without allocation: the 52-byte header (its CRC-32 over the payload first), then FNV over the header and the payload, byte-identical to hashing `export`'s bytes (asserted). Written as `fnv1a64:<16 lowercase hex digits>` on both lines.

## R-04 `SpeedPlace` and map (c)

**Decision.** The integer state of `SpeedStage` that decides places and levels (`p5`, `active`, `requested`, `latched`, `fade: Option<Fade>`, `last_p5`, `stored`, `own`, `tail`, `final_count`) moves into `pub(crate) struct SpeedPlace` with `fn step(&mut self, request: Option<u32>) -> Step` (the branches' k and p5, the fade index, the latch) called once per output exactly where `apply_request` and the fade bookkeeping run today; `SpeedStage` keeps the banks, the ring and the dots. The struct is placed first in `SpeedStage` so the fast path's seven scalars share a cache line. `timeline::place_at(index, host_rate_hz, start_level, unit_count, entries)` replays `SpeedPlace` from the start level over the `playback_speed` entries (the others ignored) mapped by `speed_landing(position, rate)`, and returns `PlaceState(i)`: the state after the requests landing on device output i are applied and before its step (`place_fifths`, `level`, `fading`, `old_place_fifths`, `latched`). Bit-identical by construction; the speed and changes goldens and the A/B (levels 3 and 5, 3 %) guard the refactor. Fallback if the A/B fails: an independent `timeline::SpeedWalker` pinned to `speed_device_outputs`.

**Corner cases pinned** (US3 AS3, ten): a request on the first output; one landing on a fade's last output; a waiting request equal to the active level; a level-3 request during a wait; a request at or after the latch; two requests inside one fade; a deferred level-3 switch overtaken by the latch (019 T023's case); a waited request equal to the old level (a fade back); two entries landing on one device output (the later wins); a request in the tail.

## R-05 The slot block and the footprint

**Decision.** `SlotBlock { counter: u64, settings: Settings, remaining_samples: u64, events_total: u64, changes_total: u64 }` (about 152 bytes) in `Memory.blocks: Vec<Option<SlotBlock>>`, capacity `max_recordings` at construction (15 KB at 99; the one-mebibyte footprint test uses the default), parallel to `spans`: pushed at `open` (the counter read before `wrapping_add`, the settings after the adopt, which precede the open), popped on `close(false)` and `discard_in_progress`, removed on `erase`, `None` on `import_samples`/`import_frames`, cleared on `erase_all`, copied by `copied_to` (so a memory-keeping `reconfigure` carries them and re-reserves). The totals: `events_total += 1` in `write_event`, `changes_total += 1` at a record-stream landing (cold paths). `new_at_counter(settings, counter)` passes the counter through `with_memory` as `reconfigure` does, keying the one-pass capsule to it from its beginning.

## R-06 The self-stop cell and the recipe

**Decision.** The record carries `run.remaining_samples_at_start` (`remaining_samples` before `open`; whole frames with the codec on, since the capacity rounds down to units). The harness's self-stop cell pre-fills the original's memory by **import** of an exported filler (`stored_recording`'s pattern: a 6 kHz `bypass_all` engine with the target's codec setting records zeros, exports, the target imports) so the recording of interest stops itself; the re-render engine imports a filler of `capacity − remaining` before `start_recording`. Never by recording: a recorded filler consumes the counter (the digest then fails; a test shows it) and silence in drop mode stores nothing. The stimulus ends in voice and the cell asserts the gate was open at the stop (`flush.paused == false`), so the "stop one frame earlier" delta moves the digest.

**The recipe (`examples/re_render.rs`; `--demo <dir>` writes a record and a raw `.i24` at a rate so the command is runnable):** read the record → `Settings` from its configuration → `Pipeline::new_at_counter(settings, counter)` → import the filler → `start_recording` → `schedule_change(Stream::Record, …)` per `change.<i>` in order, refilling when 64 are pending → feed the raw audio through `samples_from_i24` in blocks up to `stop_input_position` → `stop_recording_with_changes` when `run.stop = stop_call`, else the self-stop has occurred → `export` → `fnv1a64` → compare.

## R-07 The stop position and the padding

**Decision.** `stop_input_position` = the record stream's input position when `stop_recording` is entered (before the flush); for a self-stop, `input_samples_total` (the feed returns at the fill; nothing after it is pushed) and the `StopFields` from a `RecordInfo` say so. `padding_start_sample` = `represented` (the kept count after the latency flush) with the codec on; the length with it bypassed, after a self-stop, and when the flush itself fills the memory (the padding loop is skipped). `run.stop = stop_call` whenever the host called the stop, even if its flush filled the memory (the re-render must call it too); `memory_full` only for a self-stop. `input_samples_total` keeps spec 017's meaning; `silence_fed_samples` stays the post-gate device count of the padding (≤ 179).

## R-08 The C structs

**Decision.** `RrDr60StopOutcome` grows 64 → 80 bytes (two `uint64_t` appended; no size field; the C doc and the CHANGELOG say so; the pre-1.0 ABI pass adds size fields). New structs, each with `struct_size` first and spec 018's prefix-fill rule: `RrDr60StopFields`, `RrDr60RunData { struct_size, events, event_count, changes, change_count, stop: RrDr60StopFields }`, `RrDr60RecordReadout` (identity scalars, the flags, a `RrDr60Settings`, the counts), `RrDr60InputAlignment { struct_size, centre, first, last, clamped }`, `RrDr60PlaceState { struct_size, place_fifths, level, fading, old_place_fifths, latched }`. Statuses 31 `UNKNOWN_RECORD_VERSION`, 32 `MALFORMED_RECORD`, 33 `MISSING_RECORD_FIELD`, 34 `RECORD_CHECKSUM_MISMATCH`, 35 `INCONSISTENT_RUN`. `RrDr60ChangeEntry.reserved` keeps its C name (the stream word since 0.20); `ffi_parity` asserts `reserved == stream`.

## R-09 The writer's length

**Decision.** `len` is exact (the counting sink); `write` refuses a shorter buffer with the existing `BufferTooSmall`. No pre-sizing bound is published: the guide says call `_len` first (one counting pass, off the audio thread).


## Figures and restatements at implementation (2026-10-31)

**The A/B** (`scripts/ab-timing.sh 01a61ca record_contract`, solo, this machine, 45 runs × 3 alternations, 48 kHz, 4096 blocks, the codec bypassed): the record path 49.18 → 49.09 ns per host sample (**−0.09 ns, −0.18 %**), the one-pass 74.82 → 74.99 ns (**+0.17 ns, +0.22 %**), playback level 3 26.45 → 26.44 ns (**−0.01 ns, −0.02 %**), level 5 29.05 → 29.31 ns (**+0.25 ns, +0.87 %**); all four PASS at 3 %. The CI runner's figures come from the PR's `ab-timing` label (ceiling 5 %).

**The maps** (`record_contract_matrix::maps_at_every_rate`, device samples): map (a) 0.00 / 0.00 / 0.38 / 0.54 / 0.75 / 0.68 / 0.69 and map (b) 0.00 / 0.00 / 0.00 / 1.00 / 1.00 / 1.00 / 1.00 at 6 / 8 / 16 / 44.1 / 48 / 88.2 / 96 kHz on the tone-burst markers (the twin's detected onset against the burst's host position; the splice arithmetic bit-exact on every kept sample); the impulse through `record_only` 1.00 (b) and 1.00 / 0.75 / 0.38 / 0.41 / 0.25 / 0.27 / 0.31 (a); the one-pass 0.00 / 0.75 / 0.38 / 0.54 / 0.38 / 0.54 / 0.50; the codec-on envelope correlation **3 / 4 / 4 / 5 / 4 / 1 / 5**, and the same alignment read with `record_latency_samples()` misses by **exactly 180** at every rate.

**Restatements** (each a dated note; the spec's Clarifications carry them):

- **R-04, the walker instead of the factoring (T018).** The plan's primary choice, `SpeedPlace` factored out of `SpeedStage`, was not made: the stage's fast path and its four mutation hooks interleave with the place arithmetic, and the fallback the plan named (an independent walker in `timeline`, pinned against a per-output place trace of the stage) carries no hot-path risk. `timeline::place_at` replays the stage's rules (the latch, the wait, the deferred switch into level 3, the first-output switch, the crossfade's length) and equals the stage's own trace (`__test_hooks::speed_place_trace`, 2048 entries per call) on ten schedules at seven rates; the sixth mutant (no wait) is a second walker. The A/B on playback at levels 3 and 5 reads −0.02 % / +0.87 %: the stage is untouched but for the trace hook under `__test-hooks`.
- **R-01, the codec-on tolerance.** The plan's "±2 device samples (spec 008's figure)" was a waveform cross-correlation on continuous speech at 8 kHz. On the markers a CELP-decoded 50 ms tone burst reproduces at a quarter of the input's peak and a waveform correlation locks one 1 kHz period (6 samples) off; voiced bursts correlated by their rectified 12-sample envelopes read 1 – 5 device samples by rate. The assertion is **≤ 6 device samples (1 ms)**, the figures reported; the kept-domain rule (no 180 shift) is pinned separately by the full-latency reading, which misses by exactly 180 at every rate.
- **R-01, the gate's onset.** A burst's first 20 ms (`vas.onset_ms`, 120 device samples) are consumed before the gate opens, so `input_to_kept` of a burst's first sample reads as removed and the kept onset sits one gate onset after the burst; the markers test a position 40 ms into each burst (kept) and 5 ms in (removed), and the twin's onset for the latency convention. The codec-off stop finds the gate paused and adds no event (four events); the codec-on stop holds the gate open for its flush and adds a fifth.
- **R-06, the named deltas.** `agc.knee_dbfs` −1 dB on a −1 dBFS knee is never reached by −20 dBFS voice and leaves the digest unmoved (hardware B3's point): the delta moves the knee to **−30 dBFS**, and the changes cell's scheduled knee entry lands at −30 dBFS too so that it is effective. A limiter entry moved by one device sample is effective only when the landing sample exceeds the knee (at 8 kHz it did not), so the one-device-sample move is the **hiss entry's** (its 20 ms ramp moves with it), asserted with the codec bypassed; with the codec on the knee entry moves by **0.1 s** (a one-sample move need not flip an 80-bit frame). The rounding: one device sample later is ⌈rate ÷ 6000⌉ host samples (at 8 kHz one host sample can land on the same device sample).
- **R-05, the footprint figure.** `footprint_bytes()` keeps spec 008's formula (the store plus the span table, pinned by `codec_edge_cases`); the slot blocks (about 152 bytes per configured slot, reserved beside the span table with the same capacity) are not in it, documented on `SlotBlock`.
- **R-02, the reader's host-rate flag.** `record::read` is pure and cannot know an engine's rate, so `HOST_RATE_DIFFERS` is set by `Pipeline::processing_record_read` (C: `rr_dr60_processing_record_read` with a live handle; a NULL handle is the pure read).
- **The one-pass map** takes the one-pass's latency as an argument (`Pipeline::latency_samples()`), not the settings: the one-pass's latency depends on both halves' group delays and the tap, which only the engine computes.
- **The C API** has twenty-one functions rather than fourteen (`rr_dr60_record_write` the pure writer, `rr_dr60_processing_record_rewrite`, the three batch reads, `rr_dr60_recording_counter_of`, `rr_dr60_record_latency_pre_encoder_samples`) and five structs with `struct_size`; `RrDr60StopOutcome` 64 → 80 bytes; `RrDr60ChangeEntry.reserved` keeps its C name.
- **The self-stop's padding start** from a `RecordInfo` is 0 and the writer fills the length in; with the codec on the stop's padding runs to the frame boundary plus the 60-sample look-ahead (`silence_fed_samples` = length + 60 − represented).
- **Allocation.** `place_at` collects the schedule's speed entries into one `Vec` per call (one allocation, bounded by the log's length); the other maps, the writer, the reader and the processing path allocate nothing (`alloc_free::record_contract_allocate_nothing`).

- **Mute mode** (hardware B1 at implementation): a muted region is stored (the event's length counts kept zeros), so R(k) ≡ 0, map (b) reports a position inside a region as `Muted { kept, event_index }`, the event rows carry the region's start, and the one-pass map takes a `drop` flag. The matrix's eight mute cells had passed because the rows do not enter the digest; the mute-mode markers now pin them (every kept index equals the pre-gate index; every row's host position below the input total; the writer refuses a row at or past it).
- **The end clamp** (hardware B9): map (a) clamps its centre and ends at the stop's input position (the audio the app holds), not the input total; a kept sample of the flush or the padding reads clamped.
- **The signed figures** (hardware B7): the impulse peak sits one device sample *before* the 1 kHz group-delay convention at every rate (the record band-pass's largest tap is h[0]), and the ≥ 44.1 kHz markers' detected onsets one device sample early (the decimator's kernel smears the leading edge): every deviation is content at or before the convention, never after; the impulse test asserts −1 ≤ d ≤ 0. The formula does not move.
- **The playback A/B** (hardware B11): +0.87 % at level 5 is the hooks build's per-output place trace, which production does not carry.
- **The codec-on figure** (hardware B8): the decoded output's envelope lands within 1 ms of the map; the figure measures the decoder's own delay and the reader's resolution, not the map.
