# Research: Per-Block Meters (016)

Each entry: decision, rationale, alternatives. Code references are to `main` at the 0.14 merge (fe82f46). The plan reviews of 2026-10-30 (coach 1 – 13, hardware P1 – P12, product M1 – M7) are applied; the entries say where.

## R-01: Where the meters are accumulated

**Decision.** Crate-private accumulators live in the path objects: `RecordPath` (the input and limiter-input peaks, the limiter's largest entry voltage), `RecordHalf` (the record-filter peak, the ADC-clamp count), `PlaybackPath` (the reconstruction peak) and `OutputChain` (the route peak, the output-clamp count). The `Pipeline` holds one public `Meters` read-out and, at the end of every non-empty processing call, **finalizes** the accumulators into it: narrows the peaks, converts the limiter's voltage to dB and to the charge ratio, reads the VAS state and countdown, and clears the accumulators.

**Rationale.** The per-sample loops already exist in four places (`OnePass::tick`, `RecordPath::step`/`front`/`front_only`, `PlaybackPath::push_wide`/`try_next_host`, the transport's `feed_one` and the play loop). Accumulating where the sample is means the five call sites (one-pass, record, stop flush, play, drain) share one code path per figure, and the transcendental work (`ln`, `exp`) runs once per call (D6).

**Alternatives.** Accumulators on the `Pipeline` fed by the paths' return values (rejected: the points before the clamps and at the limiter's entry are inside the paths); two read-outs (rejected by D2).

## R-02: The points of reading, per sample

| Meter | Where (code) | Per-sample work |
|---|---|---|
| input peak (a) | `RecordPath::front` and `front_only`, after `sanitize_in(x)` | `abs`, compare-select on an f64 |
| limiter-input peak (b) | `RecordPath::front`, after `self.mic.process(..)` (stage 2's output; with both stages off `MicFront::process` is the identity, D7; `process_upto(.., MicStop::Amp)` is literally `process`, so the `AfterMicAmp` tap reads the same point). At `Tap::AfterMicCapsule` `front_only` stops before stage 2: rest | as above |
| gain reduction (c) | `Limiter::process` reads `vc` at entry and applies `a(vc) = 1/(1 + exp(vc·INV_2VT)·INV_K1)` above `v_floor`, exactly 1.0 below; `a` is strictly decreasing in `vc`, so the call's deepest applied gain is `a(vc_max)` exactly. The accumulator keeps `vc_max`, the largest entry `vc` of the call, updated **inside the above-floor branch** (below the floor the gain is 1.0 and `vc_max` stays 0, which reads 0 dB; hardware review, verified); finalization computes `−20·log10(a(vc_max))` once through `rr_dr60_detmath` (`exp`, `ln`), as `gain_db` does, and 0 when `vc_max < v_floor` | one compare-select on a local the limiter already holds, only above the floor |
| hold charge (d) | the limiter's `vc` after the call's last sample, `vc / v_limit` (≤ 1 by construction: `process` clamps `vc` at `v_limit`); `v_limit = vc_of_gain(10^(−40/20))` depends on `K1` alone, so the ratio is settings-independent | none per sample; one division at finalization |
| record-filter peak (e) | `RecordHalf::process`, after `self.record.process(d)`, before `self.clamp.process(d)` | `abs`, compare-select |
| ADC-clamp count (f) | `RecordHalf::process`: the clamp's output ≠ its input (bypassed, `process` returns `d` bit-exact, so the test is exact and needs no `enabled` branch) | one compare, one conditional increment |
| state (g), hang remaining (h) | finalization: `VasStage::is_paused()` and a new `VasStage::hang_remaining()` = `hang.saturating_sub(silent)` while recording (0 exactly at the last kept non-sound sample: the gate keeps while `silent ≤ hang`), 0 while paused; `hang` when the gate does not run (`run_vas` false) | none per sample |
| reconstruction peak (i) | `PlaybackPath::try_next_host`, on `y` (the interpolator's or the pending slot's output) before `self.chain.process(y)`; accumulated unconditionally, **finalized only when `meter_playback`** (R-03) | `abs`, compare-select |
| route peak (j) | `OutputChain::process`, on `r = self.inner(y)` before the bound, **only when the chain's tap is the route output** (`tap == Tap::RouteOutput`, a construction-time flag like the clamp gate; the player's chain is always at the route output; also with every chain stage off, since `inner` then passes `y`) | `abs`, compare-select |
| output-clamp count (k) | `OutputChain::process`: `bound(r, ..) != r`, inside the existing `if self.clamp` | one compare, one increment |

Accumulations are `if a > p { p = a }` on f64 locals (B9): no NaN can reach them (`sanitize_in` makes the input finite; every stage is finite on finite input), so the NaN-aware `f64::max` is avoided (spec 010's lesson). Each peak is narrowed **once per call** with `narrow_out` (round to nearest even, a subnormal flush, saturation to ±`f32::MAX`: each monotone non-decreasing and odd-symmetric), so `narrow(max|xᵢ|) = max|narrow(xᵢ)|` including ties and signs (`|narrow(x)| = narrow(|x|)`, −0.0 → 0), and the figure equals the largest absolute narrowed tap output exactly (spec FR-005; hardware review, verified). The harness mirrors `narrow_out` (not a bare `as f32`) when it narrows its own copies.

## R-03: The one-pass, the taps and the two playback flags

`OnePass::tick` has three routes: the front tap (`front_only`), the test-only wide route (no meters; `narrowing_delta` does not read them), and the normal route. **The record group** follows the data with no new branching: at a front tap only (a) and, at `AfterMicAmp`, (b) are read; `AfterAgc` runs `front` (a – d) but no `RecordHalf`; `AfterRecord` runs the half with `run_vas` false (e, f read; g, h rest); `AfterVas`/`AfterDecoder` the whole record group. A record-group meter rests iff its point is not on the call's path.

**The playback group needs two construction-time flags** (coach 4, P3), because `PlaybackPath::new` builds the interpolator for every tap but the front taps, so `try_next_host` yields samples at `AfterRecord`, `AfterVas` and `AfterDecoder` too, where the spec's tap table says the group rests; and because stage 10 bypassed is the identity, so the reconstruction peak must read when `playback_stage_enabled` is false (D7):

- `meter_playback = !honour_tap || settings.tap.is_after_stage_10()` on the `PlaybackPath` (the player: always true). The reconstruction peak is accumulated unconditionally (no per-sample branch) and finalized as rest when the flag is false.
- `meter_route = tap == Tap::RouteOutput` on the `OutputChain` (the player: true), gating the route peak and the count at their point of reading (they are inside `process`, where the clamp gate already branches).

So at `AfterPlayback`, `AfterVolumeAmp`, `AfterSpeaker`, `AfterEarphone` the reconstruction peak reads and the route figures rest; at `RouteOutput` all three read; at every earlier tap the group rests (spec Edge Cases, the tap list).

## R-04: The transport calls

- `record`: `feed_one` → `recorder.push(x)` accumulates; `record` finalizes at the end of the call when at least one sample was fed.
- `stop_recording`: `feed_zeros` runs the same path; the stop finalizes once after the whole flush (one read-out for the flush); a skipped flush (`!fed_any`) does not finalize. With `force_open` the half's VAS state machine still runs (verified), so (g, h) report it (B11).
- `play`: the loop pushes device samples and pulls host samples; finalizes when `produced > 0`. The drain pushes zeros through the same path, so the playback group reads its settle.
- `start_recording`, `start_playback`, `stop_playback`, `erase`, `erase_all`: no finalization. `reset` and `reconfigure` set the read-out to the engine's rest (`rest_meters`, R-05) and clear the accumulators.
- The one-pass's `run_block` finalizes when `out.len() > 0`.

**Rule:** a call finalizes iff it processed at least one host sample (the one-pass, record, play) or fed at least one flush zero (stop). The state read at finalization is the half's own gate (`half.vas.is_paused()`), not `RecordPath::paused()` (`run_vas && ..`); with `run_vas` false the state is "recording" and the hang the full length (FR-002 h).

## R-05: The read-out types

Rust (`rr_dr60::Meters`, re-exported from `pipeline.rs`): `#[derive(Clone, Copy, Debug, PartialEq, Default)]`, `#[non_exhaustive]`, public fields in the spec's order: `input_peak`, `limiter_input_peak`, `gain_reduction_db`, `hold_charge`, `record_filter_peak`, `adc_clamp_count: u32`, `vas_paused: bool`, `hang_remaining_samples: u64`, `reconstruction_peak`, `route_peak`, `output_clamp_count: u32` (f32 unless stated; the stage 4 names after the product review M3: the count names the setting it reports, `adc_clamp_enabled`). `Meters::default()` is the all-zero value, the C zero-struct's twin; the engine's rest carries the configured hang, so `Pipeline::rest_meters(&self) -> Meters` returns it (P7) and `new`/`reset`/`reconfigure` store it. `Pipeline::meters(&self) -> Meters` copies the read-out.

Every peak's doc comment states: linear full-scale (20·log10 for dBFS), may exceed 1.0 (the route peak up to about 2.3 on the speaker route, A-042; the record-filter peak whenever the clamp counts); the route peak's 1.0 is the amplifier's clip ceiling on the speaker route and the earphone scale on the earphone route (M4). `hold_charge`'s first sentence says "the limiter's hold capacitor" (M3).

**Why f32.** The peaks are narrowed values, exactly representable; the dB and charge figures are casts of deterministic f64 results (`as f32` is a correctly rounded IEEE operation, bit-identical across targets because the f64 is). The gain reduction's 0.01 dB tolerance is far above f32 resolution.

C (`RrDr60Meters`, `repr(C)`, 56 bytes, 8-aligned): `struct_size` 0, `input_peak` 4, `limiter_input_peak` 8, `gain_reduction_db` 12, `hold_charge` 16, `record_filter_peak` 20, `adc_clamp_count` 24, `vas_paused` 28 (u32, 0/1), `hang_remaining_samples` 32, `reconstruction_peak` 40, `route_peak` 44, `output_clamp_count` 48, `reserved_016` 52 (u32, written 0); offsets asserted at compile time (spec 010's pattern). One function, `rr_dr60_meters(RrDr60Pipeline *pipeline, RrDr60Meters *out)` (a `*mut` handle like `rr_dr60_get_volume`, through `live()`, so a poisoned handle reads `INTERNAL_ERROR` as every call does; P8 a): reads `out->struct_size` through the raw pointer first (`read_unaligned`, the `check_struct_size` pattern), refuses `< 56` with `INVALID_ARGUMENT` and nothing written, writes the 56 bytes and zero-fills `[56, struct_size)` with `write_bytes` (D5; B12). The contract states the caller's obligation: `out` is 8-aligned and `struct_size` bytes are writable; no cap on `struct_size` (P8 c, the default; a garbage size is the caller's undefined behavior as for every out-buffer). A null handle or `out` → `NULL_POINTER`. Panic-caught like every entry point.

**Alternatives.** Growing the existing reports (rejected by D5); doubles (no precision to carry); a cap on `struct_size` (an owner option; not taken).

## R-06: The record-filter-peak oracle at rates other than 6 kHz

**Decision.** A `__test-hooks` hook on the pipeline, `stage4_trace(&mut self, x: f32) -> Option<f64>`: one host sample through the one-pass's record path's front and decimator, returning stage 4's output **before the clamp** when a device sample is due, running nothing after (the `mic_clip_trace` pattern, `paths.rs` 626). The harness runs a twin engine (same settings and seed: the hiss is keyed by the seed and the recording counter, so the twin's stream is the same) with the hook on the same blocks and takes the largest absolute value per block, narrowed with a mirror of `narrow_out`; this equals the meter exactly at every rate (verified: the front, the decimator and `half.record` are the only state ahead of the point, and nothing after it feeds back). At 6 kHz the `AfterRecord` tap with the clamp bypassed is the second, hook-free oracle (`narrow_device` is `narrow_out`; spec SC-001).

**Alternatives.** A harness-side decimator (a second polyphase implementation); comparing through the interpolator with a tolerance (not exact).

## R-07: The gain-reduction and charge oracles

**The ratio.** Per block, the one-pass output at `Tap::AfterAgc` divided by a twin's at the same tap with `agc.enabled = false` (stages 1 – 2 bypassed in both, so the limiter's input is the stimulus; spec 002 R-11), on samples whose reference magnitude is at least −60 dBFS; the deepest ratio in dB must be within 0.01 dB of the meter on every block, onset blocks included (B8: the attack ramps about 1 dB per host sample at 48 kHz at the default settings, so a meter reading the post-update state is caught). **Block-length rule** (P5): the 1 kHz tone from `stimulus::peak_phase` has exact-zero samples at some rates (48 kHz at k ≡ 12, 36 mod 48), which the −60 dBFS rule excludes; if a block's last sample is such a zero, the oracle's deepest sample is one earlier and the meter is deeper by one ramp step. The test uses block lengths that are multiples of 4 from the stream's sample 0 (64, 120, 4096 are safe) and asserts that every block's last sample qualifies, so a violation fails loudly.

**The steady figures** are pinned per host rate (P6) to the script's "## Charge (spec 016)" print (`emulate()` on the +10 dB-over tone, the last 0.1 s of 1 s; T003, 2026-10-30): steady mean gain −9.9933 / −9.9930 / −9.9887 / −9.9542 / −9.9517 / −9.9512 / −9.9521 dB at 6 / 8 / 16 / 44.1 / 48 / 88.2 / 96 kHz (the deepest in the window −10.0000 / −10.0000 / −9.9962 / −9.9630 / −9.9595 / −9.9597 / −9.9599: the meter is the deepest, within the 0.1 dB tolerance) and steady charge ratio 0.84404 / 0.84404 / 0.84401 / 0.84377 / 0.84376 / 0.84375 / 0.84376 (1 % tolerance).

**The charge.** `__test_hooks::limiter_state` (the capacitor voltage) divided by the script's literal `v_limit` (1.27538 V) must equal the meter within 1e-3 after every block (the literal is pinned to the engine's own `v_limit` through the new `limiter_v_limit` hook within 0.002 V in the core landmark test, as `limiter.rs` 773 does; dividing by the hook alone would be circular, P12). The landmarks (the script's print: v_limit 1.27538 V, v_floor 0.17139 V; floor 0.1344, 1 dB 0.7269, 10 dB 0.8441, 20 dB 0.9022, 40 dB 1.0000) are printed by the script and asserted by a core unit test from the limiter's constants. The "exactly 0 after the flush length" case (about 140 s of silence) is release-only at 6 kHz (coach 9).

## R-08: The VAS oracle

A harness `ReferenceGate` (`meters_checks.rs`): the state machine of spec 003's data model (`specs/003-vas/data-model.md` 94 – 105 is complete pseudo-code: threshold, hang, onset, the W bridge, the `silent`/`run`/`since_sound` counters), written from it, not from `vas.rs`, fed the harness's own device-rate copy of the post-clamp stream (the `AfterRecord` tap at 6 kHz; at other rates the `stage4_trace` hook's output through the harness's clamp). Per block it yields the state and `hang − silent` (0 while paused), which must equal the meter; and a cumulative drop count D.

**Corroboration by the engine's reports** (P4): `BlockInfo.paused`/`RecordInfo.paused` equals `vas_paused` after every call; at each drop-mode resume the splice event's `input_length` equals D since the flip in the recorder (device positions) and ⌊D·m/l⌋ − ⌊D_prev·m/l⌋ in the one-pass (host output positions with the cumulative-floor rule, `paths.rs` 355 – 364); in mute mode the muted-region event's start lies within the device samples of the call whose read-out first reads paused (coach 10). Device-sample counts per block come from the twin's hook, not nominal arithmetic (spec 003's lesson at 44.1/88.2 kHz).

## R-09: The cost measurement

There is no off switch (D6), so the budget is a **build comparison**, and the script as it stands cannot make it (coach 1 – 2, P1: `ab-timing.sh` always runs the baseline's `output_cost`, stages 1 – 2 off, and only prints). **Decision.** A new release-only `crates/rr_dr60_harness/tests/meters_timing.rs`, written against the 0.14 public API, that prints two figures per run at 48 kHz, 4096-sample blocks, the speaker route, −20 dB noise (the limiter stays uncharged, asserted by `limiter_state == 0.0`): **default front** (`configs::settings("default_output", 48_000)` with `MicSettings::DEVICE`, the speech codec bypassed: "the default engine" as specs 009 – 013 measure it, P10) and **every stage off** (`bypass_route_output`: stages 1 – 2, the limiter, stage 4, the clamp, the VAS, the codec, stage 10 and the chain all off, at `RouteOutput`). A `meters` mode of `scripts/ab-timing.sh` copies the test into the baseline worktree (the `playback` pattern), runs both builds 45 times strictly alternating, takes the fastest of each, and its Python **asserts and exits non-zero** when `head_default / base_default − 1 > ceiling` or `head_off − base_off > ceiling × base_default` (the bypassed chain's budget in the same absolute nanoseconds), the ceiling from `RR_DR60_METERS_COST_CEILING` (default 0.05; the `ab-timing` label's workflow step sets 0.12). The local figures are quoted from a solo run.

**Measured (2026-10-30, solo, `scripts/ab-timing.sh fe82f46 meters`, 3 alternations of the fastest of 45 runs):** the default front (stages 1 – 2 on, codec bypassed, speaker route, 48 kHz, 4096 blocks) **69.81 → 70.75 ns per host sample, +0.94 ns (+1.34 %)** against the 5 % ceiling; every stage off **58.20 → 59.27 ns, +1.07 ns** against the 3.49 ns budget (5 % of the baseline front). Both pass. The first script draft read nothing: with `--nocapture` libtest prints the test's name on the same line as its first figure, so the extraction is unanchored (`grep -oE`).

**Expected cost.** About 6 compare-selects per host sample at 48 kHz (three host-rate peaks, two device-rate figures at 1/8, the chain's count only when clamping; the limiter's compare never runs on the uncharged noise) ≈ 1.5 – 3 ns against 73 ns on the default front: 2 – 4 % (B9); the every-stage-off path is about 45 – 50 ns, where the same nanoseconds are 3 – 6 %, hence the absolute budget. If the first measurement exceeds the budget, the fallback is a per-block pass over the input and output buffers for (a) and (j) after the loop (vectorizable) before any decision.

## R-10: The golden file and the C parity

`golden-meters-v1.json`, generated by `golden::generate_meters`: entries = stimuli × configurations × 7 rates, each with the one-pass rows and the record-then-play rows. **Stimuli, 0.5 s each** (so every block's read-out fits; coach 8): `voiced_m20_half` (`stimulus::voiced(fs, 0.5, −20.0, 0x0D60)`), `vas_burst` (0.1 s of 1 kHz at −20 dBFS, 0.25 s silence, 0.15 s burst: the countdown reaches 0, the gate pauses and resumes within the rows), `limiter_step` (+9 dBFS 1 kHz from `peak_phase`), `clamp_square` (`smoke_reference::clamp_stimulus()`'s ±1.0 square, 24 up / 24 down, exactly representable: the C smoke's stimulus). **Configurations:** the 0.14 default; the default with the output clamp on; `settings_011` with the limiter and the ADC clamp; the chain-only configuration; `meters_short_hang` (`vas.hang_ms = 50`, `onset_ms = 20`, drop mode, stages 1 – 2 off) and its mute twin (P2: the default 1.0 s hang never pauses within 0.5 s). **Block sizes:** 1024 host samples for the one-pass, `split_checks::RECORD_BLOCK`/`PLAY_BLOCK` for record-then-play. Each `GoldenEntry` gains an optional `meters` object (data-model.md): `blocks` (the one-pass rows), `record_blocks`, `flush`, `play_blocks` and `drain_blocks` (every drain call's row), the f32s as 8-digit hex bit patterns; the record entries carry the `seed` and `counter` fields as the mic golden does; the entry's `sha256` stays the one-pass output's, so the entry also proves the audio unchanged; a `digest` replaces the rows for any later stimulus over 0.5 s (none at v1). Bless-time assertions: the four route-output identities (b, i, j, k) on every entry, and a paused row and an event in each short-hang `vas_burst` entry (the other identities are proven by the story tests at every rate). The nine earlier files and their guards are untouched.

**C parity** (coach 3, P9): the C smoke's `--meters` case runs the default engine at 48 kHz with the output clamp on over the `clamp_square` stimulus in 1024-sample blocks and prints each block's eleven figures with the floats as bit patterns (`memcpy` to `uint32_t`, `%08x`); `run_smoke.sh` diffs it against `examples/meters_rows.rs`, which prints the same golden entry's rows (the 007/014 pattern). `ffi_parity meters` compares the voiced stimulus's read-outs in-process through the FFI crate.

**Determinism** (coach 12): partition identities: for any partition of a stimulus into blocks, the maximum over the rows of each peak equals the one-block row's peak, the counts sum to the one-block count, and the final state, hang and charge equal the one-block row's; two engines with the same seed give identical rows.

## R-12: Test hooks and mutants

Hooks (`__test-hooks`): `stage4_trace` (R-06), `limiter_v_limit` (R-07), and `MeterMutation { filter_peak_after_clamp, gain_from_state_after_update, hang_off_by_one, skip_clear }` with `Pipeline::__with_meter_mutation(settings, &m)` (the `OutputMutation`/`MicMutation` pattern; coach 5).
