# Tasks: Optional Output Clamp (a host option at the route output)

**Input**: Design documents from `specs/010-output-clamp/`: [plan.md](plan.md) (› "Task order"), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/](contracts/) (rust-api, c-api, golden-format), [quickstart.md](quickstart.md).

**Tests**: REQUIRED. Constitution III says tests are written first and must fail before the implementation exists. Every story phase lists its tests before its implementation tasks; the identity check is written and run red against the unchanged chain before the core change (plan › Task order 2).

**Organization**: Setup (the version bump and the one canonical re-bless, the stimuli and configurations, the inert setting) → US1 (P1, MVP: the bound at the route output, the taps, the figures) → US2 (P2: the whole engine) → US3 (P3: registers, README, CHANGELOG, wording) → US4 (P4: the C surface) → Records, gates, reviews, the golden bless, the PR.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: the user story the task belongs to (US1 – US4)
- Paths are relative to the repository root.

## Conventions that apply to every task

- **Traceability**: cite spec 010 FR, SC and A-042 in code comments, rustdoc and test names, e.g. `// A-042: the route's full scale (spec 010 FR-001)`, `// 010 FR-003: the route-output tap only`, `// 010 FR-005: the identity on == clamp(off)`.
- **The five golden files do not move** (FR-002): `golden`, `golden_agc`, `golden_vas`, `golden_codec`, `golden_output` and their SHA guards stay green through every task; every pre-010 configuration carries `clamp_enabled = false` through `OutputSettings::BYPASSED` / `DEVICE`.
- **The identity is the oracle** (FR-005; research R-01, R-06): every check of the option compares the option-on output with the option-off output bounded sample by sample with `f32::clamp(-1.0, 1.0)`, bit for bit; the option-off peaks and counts are **reported**, never toleranced, except that the four overshooting stimuli must exceed 1.0 and the reference configuration must not, and the speaker route's peaks must not exceed the L1 bound (R-04).
- **Naming** (research R-05): every new name carries the `output_clamp` prefix; "clamp" alone names the codec's full-scale clamp (A-030). A manifest wording check searches for "output clamp" and `clamp_enabled`, never "clamp".
- **The bound function** (R-01): `fn bound(y: f64, b: f64) -> f64 { if y > b { b } else if y < -b { -b } else if y == y { y } else { 0.0 } }`; no `f64::clamp` in the per-sample path; the gate is decided at construction, never read from the settings per sample.
- **Wording** (FR-004; R-07): "the output clamp", "an emulator convenience, not a device behavior", "bounds" / "replaces" for the option, "clip" for the amplifier; never "accurate", "protects", "safe for", "hearing", "loudness limit", "the device clips here", "prevents clipping"; the word "verified" stays out of the CHANGELOG entry (the denylist stem `verif`).
- **Story boundaries (Principle VII)**: `us1_output_clamp.rs` uses engines and the `output_clamp_*` configurations (no registers, no C); US2 reuses the 006 – 009 equivalence, determinism and allocation harnesses; US3 the cross-check; US4 compares C with Rust.
- **Real-time safety**: the per-block calls allocate nothing (`alloc_free`); the bound has no state; the per-sample path has no assertion.
- **Measurement lessons that apply**: a 1 kHz tone at 6 kHz has six samples per period, so a sample-peak reads 1.5·sin 60° = 1.299 for an amplitude of 1.5 (report the count beyond the bound, not the peak); `output_clamp_matrix` uses 1 s stimuli so its counts reproduce R-04; the golden uses 2 s; `cargo test --test a --test b NAME` filters every binary by NAME; a throwaway harness test needs the crate doc comment or the missing-docs lint fails it.
- **Before ticking a task**: `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -- -D warnings` and `cargo test --all-features` must pass (inside a story's test-first window, that story's new tests are the expected red). The MSRV gate is `RUSTFLAGS="-D warnings" cargo +1.85 test --workspace --all-features --no-run`.
- **Commits**: Conventional Commits, on branch `010-output-clamp`, after each task or logical group. Merge to `main` only through a green PR, and only after the user says so.
