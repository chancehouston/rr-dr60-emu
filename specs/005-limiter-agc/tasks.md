# Tasks: Limiter-Type AGC per the Schematic, ADC Full-Scale Clamp, VAS Threshold Re-anchored

**Input**: Design documents from `specs/005-limiter-agc/`: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md); the committed reference model [tools/agc-model/limiter_model.py](../../tools/agc-model/limiter_model.py).

**Tests**: REQUIRED. Constitution III says measurement tests are written first and must fail before the implementation exists. Every phase lists its tests before its implementation tasks. For this feature "fail first" has two shapes: the core unit tests are written against the limiter model (research R-02 – R-05) and fail because the modules do not exist; the harness checks are written against the spec 005 figures and fail against the spec 002 compressor until the core is replaced (Phase 2) and the harness restated (Phases 3–5).

**Organization**: Setup → Foundational (the core swaps the compressor for the limiter at the host rate, adds the clamp, replaces the settings and the C struct, drops the Hilbert detector; harness compiles) → US1 (P1, MVP: the limiter measured at the host-rate tap at seven rates) → US2 (P2: the VAS threshold re-anchored, the chain scenarios) → US3 (P3: settings matrix, tap, C parity, the single golden re-bless, CHANGELOG, records) → CI → Polish.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: The user story the task belongs to (US1, US2, US3)
- Paths are relative to the repository root.

## Conventions that apply to every task

- **Traceability**:
  - Cite spec 005 FR, SC and A-/S-IDs in code comments, rustdoc and test names, e.g. `// S-002: R11 10 MΩ`, `// A-028: knee +1 dBFS`, `// A-034: dead time`, `// A-035: release`, `// A-036: positive polarity sensed`, `// A-030: full scale`, `// A-022 (revised by 005): −40 dBFS`.
  - Constants that are not device properties are commented `// engineering target (005 FR-0xx)` or `// engineering target (005 R-xx)`; the list is research R-13. Circuit constants cite S-002; transistor estimates cite A-028.
  - Harness results cite requirements as `005/FR-0xx`; VAS results that spec 003 defined keep `003/FR-0xx` and add `005/FR-012` where the threshold is restated.
- **Determinism**: in `rr_dr60`, only basic IEEE operations and integer arithmetic on the processing path, plus `rr_dr60_detmath::{exp, ln}` per sample (research R-02; spec 002 allowed it) and `rr_dr60_detmath::{sin, exp, ln}` at construction (the mapping, research R-05). No platform libm (`clippy.toml` enforces this). The Rust build never runs Python.
- **Real-time safety**: no new allocation, formatting or I/O in any processing path. The limiter's state is one `f64` plus parameters fixed at construction.
- **The golden window**: from the core swap (T016) until the re-bless (T044), `golden_agc`, `golden_vas`, the `GOLDEN_AGC_V1_SHA256` guard and the AGC and VAS mutation golden checks are **expected red**, and so is every AGC or VAS harness test whose figures have not yet been restated. **`golden` (spec 001) and `GOLDEN_V1_SHA256` must stay green for the whole feature** (FR-016): a difference there is a defect, never a re-bless. Before ticking a task in the window, this must pass instead of the full suite: `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test -p rr_dr60 -p rr_dr60_detmath -p rr_dr60_ffi --all-features`, `cargo test -p rr_dr60_harness --test golden`, and every harness test binary the task touches. Each checkpoint names what is expected red. From T044 on, `cargo test --all-features` must be fully green before ticking anything.
- **One re-bless**: `RR_DR60_BLESS=agc` and `RR_DR60_BLESS=vas` are run exactly once in this feature, in T044, together with the CHANGELOG entry (FR-016). `RR_DR60_BLESS=1` is never run. Any later golden difference is a defect.
- **Never widen a spec tolerance** to make a test pass. If the Rust model lands outside a spec figure, the plan is wrong (research R-15): stop, re-run `python3 tools/agc-model/limiter_model.py`, and raise it with the user.
- **Phase rule**: every 1 kHz stimulus that feeds the limiter at the host-rate tap uses `stimulus::peak_phase(1000.0, host)` (research R-08); chain tests at the default output keep spec 004's `aligned_phase`.
- **Story boundaries (Principle VII)**: US1 observes the limiter only at the `agc_only` configuration (the "after AGC" tap, everything else off); US2 observes the default pipeline by output length and events (003 R-11); US3 compares outputs across settings and interfaces. No story's test depends on another story's harness code beyond `stimulus.rs` and `configs.rs` (Foundational).
- **Before ticking a task** (outside the golden window): `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -- -D warnings` and `cargo test --all-features` must pass.
- **Commits**: Conventional Commits, on branch `005-limiter-agc`. The re-bless commit (T043 + T044) is `feat!:` (breaking: the AGC model, the settings, the tap, the C struct). Merge to `main` only through a green PR, and only after the user says so.

### Risk notes

- **The pinned figures are the plan's contract** (T003, T006): if the Rust model lands outside them, the discretization or a constant is wrong, or the script and the Rust code disagree on a convention (polarity, phase, the half-steady rule). Diff the two sample by sample at 48 kHz before touching any tolerance.
- **The golden window** (T016 → T044) is long. Keep `golden` (001) green throughout: it is the proof that the clamp and the placement did not touch the 001 configurations. Do not open the PR before T044.
- **6 kHz grid**: the dead time is 14 samples (2.33 ms) at +11 dBFS; a change of one sample in either direction is still inside FR-005's ±1.5 ms, but the unit test pins it to ±1 sample on purpose. The armed dead time at 8 kHz is 3 samples (0.375 ms) against a 0.5 ms limit: the thinnest margin in the feature.
- **Flush takes about 140 s** (R-03): "released equals fresh" tests assert `limiter_state() == 0.0` directly or feed enough input; do not shorten `V_FLUSH` to make a test fast.
- **Transcendentals**: `exp`/`ln`/`sin` only from `rr_dr60_detmath`; the cross-platform golden job is the check. A platform difference is a bug, never a second bless.
- **Honesty**: "modeled on the circuit (S-002) with estimated transistor parameters", never "the device's limiter". The flat-topping versus level-ceiling question is open and said so wherever the ceiling is described.
