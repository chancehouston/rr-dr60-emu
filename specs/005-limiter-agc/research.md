# Research: Limiter-Type AGC, ADC Clamp, VAS Threshold (feature 005)

Decisions for feature 005. They revise [spec 002's research](../002-agc/research.md) (R-01 placement, R-02/R-03 detector, R-05 smoother, R-11 measurement method) and [spec 003's research](../003-vas/research.md) R-03 (the input-referred threshold). Every number below comes from the committed reference model `tools/agc-model/limiter_model.py` (R-04), run on 2026-10-11 after the plan review (positive sensed polarity, phase 0, the relative dead-time rule, the knee-aware attack mapping and the host-rate discretized loop), unless a source is cited. The transistor-level parameters are estimates (A-028, A-034, A-035, A-036); the component values are the schematic's (S-002).

## R-01 Placement: the limiter runs at the host rate, before the decimator (FR-001; spec Clarifications)

- **Decision**: `Pipeline::process` applies the limiter to each host sample before `down.push(x)` (and before the identity path's direct copy). With `Tap::AfterAgc`, the output is the limiter's output sample for sample, the rate converters are not run, `latency_samples()` returns 0 and `max_events` returns 0. `DeviceChain` loses the AGC; its order becomes record → clamp → VAS → playback. The limiter runs whether or not later stages run; with `agc.enabled = false` it is skipped without arithmetic (bit-exact bypass).
- **Consequences**: spec 002 R-01 ("the AGC runs at the device rate") is reversed. The detector sees everything the host rate carries; the device's 72 Hz–13 kHz mic-amp bandwidth is not modeled (R-14). The sample-peak reading at the identity rate (004 R-08) is a model property; the harness uses aligned-phase tones.
- **Rationale**: the reviewer's three reasons (pre-filter detector; 6 kHz loop over-attenuation; exact gain observable everywhere) and the user's decision.
- **Alternatives**: device-rate placement (rejected: Clarifications); both (rejected: one tap).

## R-02 The model: the circuit's control loop in the control-voltage domain (FR-003 – FR-007)

- **Decision**: one state variable, the hold-capacitor voltage `vc` (volts), and these per-sample steps for host sample `x` (full-scale units, 1.0 = `V_FS` = 0.7 V peak at GSX, A-030):
  1. **Shunt gain** `a(vc)`: `ib4 = IS · exp(vc / (2 · VT))` (Q5 and Q4 base–emitter drops in series), `g = (BETA_R + 1) · ib4 / VT` (saturated-transistor conductance), `r = 1 / g`, `zn = r · R10 / (r + R10)`, `a = (zn / (R7 + zn)) / (R10 / R_IN)` (the divider R7 → node → R10 into the codec amp, relative to its unloaded value). `a` is exactly 1.0 when `vc` is below the turn-on floor (R-03).
  2. **Output** `y = a · x` (no multiply when `a == 1.0`).
  3. **Detector view**: `gsx = clamp(y · V_FS, ±V_RAIL)` (the codec input amp's swing limit), sensed polarity `pol` (A-036: +1), `over = KDIV · pol · gsx − VBE6` in volts.
  4. **Charge**: if `over > 0`: `ic = min(BETA6 · over / RTH, (V_REF − vc) / R12)` (current-gain limited, then collector-resistor limited), else 0.
  5. **Discharge**: `idis = vc / R11 + ib4 / BETA5` (R11, plus the follower's base current).
  6. **Integrate** `vc += (ic − idis) · dt / C6`, floor at 0, then the **cap** (R-03).
- **Constants** (data-model.md has the table with traces): `C6` 1 µF, `R11` 10 MΩ, `R12` 390 Ω, `R13` 100 kΩ, `R17` 330 kΩ (so `RTH` = 76.7 kΩ, `KDIV` = 0.767), `R7` 22 kΩ, `R10` 1 kΩ, `R_IN` 23 kΩ, `V_REF` 1.6 V: S-002. `VT` 26 mV, `IS` 1e-14 A, `BETA_R` 5, `BETA5` 300: transistor estimates (A-028). `V_FS` 0.7 V: A-030. `V_RAIL` 1.2 V and `VBE6` 0.6 V: estimates (A-028; the rail limits the detector's overdrive and makes the dead time saturate above about +5 dB; the Vbe sets the knee). `BETA6` is derived from the attack setting (R-05).
- **Why the dynamics come out as the spec says**: the exponential law maps only about 0.1–0.25 V of `vc` to gain (0.05 dB/mV near −3 dB, 0.16 dB/mV below −25 dB), so (a) `vc` must climb through about 0.93 V (two Vbe's) before `a` drops 1 dB: the **dead time**; (b) while `vc` sits between 0.5 and 1.1 V the loop is **armed** and R11's 10 s decay keeps it there for seconds; (c) R11's 0.1 µA plus Q5's base current discharge the 0.1–0.25 V that matter in about 1–2 s: the **release**, fast at first and slower near unity because the law flattens as the shunt's resistance passes R10. The **ceiling** is where the detector stops conducting: output peak = `VBE6 / KDIV` = 0.782 V = +0.97 dBFS ≈ the knee setting.
- **Alternatives**: a dB-domain one-pole smoother (spec 002 R-05): cannot produce a dead zone or arming, and its release is exponential in dB (rejected, reviewer D2). A peak-hold-plus-ramp "limiter" with tuned dead time and release constants: four tuned numbers with no circuit trace (rejected: Principle II).

## R-03 Discretization at the host rate: the charge cap, exact passthrough, flush-to-zero (FR-003, FR-005, FR-014)

- **Problem**: at 6 kHz, `dt` = 167 µs and the current-limited charge can raise `vc` by up to 0.17 V in one sample, which on the exponential law is 8–26 dB of attenuation: a plain Euler step over-attenuates (the reviewer measured −33 dB on a +10 dB step at 6 kHz; correct at 48 kHz).
- **Decision**: after the Euler step, when the sample charged (`ic > 0`), cap `vc` at the voltage at which this sample's amplitude would no longer exceed the threshold: `a_t = (VBE6 / KDIV) / (|x| · V_FS)` (clamped to ≤ 1), then the closed-form inverse of `a(vc)`: `zn_t = a_t · (R10 / R_IN) · R7 / (1 − a_t · (R10 / R_IN))`, `r_t = zn_t · R10 / (R10 − zn_t)`, `ib4_t = VT / ((BETA_R + 1) · r_t)`, `vc_t = 2 · VT · ln(ib4_t / IS)`; `vc = min(vc, vc_t)`. This is what the continuous loop does within a sample (conduction stops when the output falls to the threshold), and since the peak sample's target is the highest of any sample's, `vc` never exceeds the static value for the largest peak seen: **no over-attenuation at any host rate** (the FR-005 guard). One `ln` per charging sample.
- **Exact passthrough**: `a(vc)` is set to exactly 1.0, and the multiply skipped, whenever `vc < V_FLOOR`, where `V_FLOOR` is the voltage at which the shunt's deviation from unity, `1 − a(vc)`, reaches 2⁻²⁴ (**0.171 V**; a derived constant, computed at construction with detmath by bisection on the closed-form inverse). (The plan's first draft said "effect below 1e-9", which has no solution: at `vc` = 0 the deviation is already 2.2e-9; plan review P4.) Below the knee the detector never conducts, so `vc` stays 0 and the output is the input bit for bit (FR-003). After a loud sound `vc` decays with R11·C6 = 10 s: it falls below `V_FLOOR` about **18 s** after a 1 s burst (gain exactly 1.0 again), and below `V_FLUSH` (1e-6 V, engineering target) about **121 s** later, at which point `vc` is set to 0.0 and a pipeline that has recovered is bit-identical in state to a fresh one (reset and partition tests; 001 R-05's flush rule). Consequence for tests: a "released equals fresh" state-equality test needs more than 140 s of sub-knee input (about 840 000 samples at 6 kHz; cheap), or it asserts `limiter_state() == 0.0` directly; the audible release (FR-006) is unaffected. No stall or denormal hazard: the `exp` argument is at most `v_limit / (2·VT)` ≈ 24.5 and `v_limit` (1.275 V for 40 dB) stays below `V_REF`.
- **Grid effects** (model properties, documented; figures from the script's discretized loop at the default settings): at 6 samples per cycle the detector sees 1–2 above-threshold samples per cycle, so the dead time is quantized to 1/6 ms and depends on level and phase: **2.33 ms (14 samples) at +11 dBFS at 6 kHz** against 3.15 ms in the 192 kHz reference; 3.25 ms at 8 kHz (quantized to 1/8 ms); 3.15–3.25 ms at 16 kHz and above. The ramp from the dead-time point to within 1 dB of the steady value is ≤ 0.12 ms at every rate (FR-005 asks ≤ 1 ms); the over-attenuation versus the steady value is −0.01 dB (the guard asks ≤ 1 dB); the armed dead time 2 s after a 0.2 s burst is 0.25–0.38 ms (FR-005 asks ≤ 0.5 ms; thinnest at 8 kHz, 3 samples). The attack setting's linearity at 6 kHz / 48 kHz: 1 ms → 1.33 / 1.15 ms, 3 → 2.33 / 3.17, 10 → 8.33 / 10.25, 50 → 41.3 / 52.2 ms, all inside FR-011's ±50 % or ±0.5 ms; the harness uses the host-grid peak phase (R-08).
- **Determinism**: `exp` and `ln` from `rr_dr60_detmath`; all other operations are basic IEEE. The state is one `f64`. Same input, settings and host rate ⇒ bit-identical on every target.
- **Implementation (T011, 2026-10-11)**: the gain law is coded in closed form, `a(vc) = 1 / (1 + exp(vc / 2VT) / K1)` with `K1 = VT · R_IN / ((BETA_R + 1) · R7 · R10 · IS)` ≈ 4.5e8, algebraically identical to R-02 step 1 (R7 + R10 = R_IN makes the unloaded divider exactly unity), and its inverse `vc(a) = 2VT · (ln K1 + ln((1 − a) / a))` is the cap. `V_FLOOR` is `vc(1 − 2⁻²⁴)` directly (0.1714 V; the bisection is unnecessary) and `v_limit` is `vc(10^(−40/20))` = 1.275 V. Below the floor the discharge drops Q5's base-current term (9e-16 A at the floor against R11's 1.7e-8 A, seven orders smaller), so the sub-floor path makes no transcendental call and the per-sample cost while charging is 28 basic operations + `exp` + `ln` (R-12). A charging sample below the floor (the start of a dead time) does call `ln` once, for the cap.

## R-04 The reference model and the numbers (A-028, A-034, A-035, A-036)

- **Decision**: `tools/agc-model/limiter_model.py` (pure Python, no dependencies) is committed and prints the design figures. It runs the same equations as R-02 twice: a 192 kHz Euler **reference** of the continuous loop, and the emulator's **discretized loop** of R-03 (charge cap, exact-unity floor, flush) at the seven host rates, with the emulator's conventions (sensed polarity +1, A-036; tones at phase 0 in the reference and at the host-grid peak phase in the emulator runs, R-08). The dead time is measured as FR-005 defines it: the first sample whose attenuation exceeds half the steady attenuation (plan review P1). A core unit test pins the Rust model's figures to the script's within the spec tolerances. Output on 2026-10-11:
  - **Static curve**: gain 0.00 dB up to +1 dBFS input; −0.98 dB at +2, −1.98 at +3, −4.97 at +6, −10.97 at +12, −18.96 at +20 dBFS; output peak +1.00 … +1.04 dBFS throughout (ratio effectively unlimited); **knee (−1 dB point) +2.02 dBFS**; the ceiling is the detector onset, +1.00 dBFS = 1.122 FS, which the ADC clamp then flat-tops for about 30 % of each cycle. Spec FR-004: +2 ± 2 dBFS, ceiling ±0.5 dB.
  - **Dead time** (reference, discharged state, step from −20 dBFS, levels 2 / 5 / 10 / 18 dB over the +1 dBFS knee): at `BETA6` 300: 11.3 / 3.2 / **2.17** / 2.1 ms; at 150: 23.3 / 6.3 / 4.3 / 3.4 ms; at 600: 5.3 / 1.3 / 1.2 / 1.1 ms. The 2.17 ms figure is `T_REF`, the reference point of the attack mapping (R-05); the default attack setting (3 ms) maps to `BETA6` ≈ 217 and realizes **3.15 ms** in the reference (3.17 at 48 kHz, 2.33 on the 6 kHz grid; R-03), **16.2 ms at 2 dB over the knee** (5.2× the 10 dB value) and **0.25 ms when armed** (2 s after a 0.2 s burst; 0.14 ms from `vc` = 1.0 V). The attenuation reaches its steady value within 0.12 ms of the dead-time point and never exceeds it by more than 0.01 dB. Spec FR-005: 3 ± 1.5 ms at +10 dB; 2 dB over ≥ 3× that; armed ≤ 0.5 ms.
  - **Release** after a 1 s burst (default settings): from 10 dB of attenuation, −1 dB after **1.36 s** (−9.2 dB at 0.05 s, −7.2 at 0.2, **−6.1 at 0.3**, −4.4 at 0.5, **−2.9 at 0.75**, −1.9 at 1.0); from 17 dB, 1.69 s. With the release setting mapped as R-05, the realized release is 0.198 / 1.362 / 3.982 / 9.957 s for settings of 200 / 1370 / 4000 / 10 000 ms (ratio 0.99–1.00). Spec FR-006: 1.37 s ± 40 %, −6 ± 2 dB at 0.3 s, −3 ± 1.5 dB at 0.75 s.
  - **Arming decay**: `vc` 1.1 → 0.5 V in 7.9 s (R11 × C6 = 10 s); gain exactly 1.0 about 18 s after the burst; flush about 121 s later (R-03).
  - **Polarity**: the asymmetric stimulus `sin θ + 0.5 cos 2θ` has peaks **+0.75 and −1.5** (6.0 dB apart; the plan's first draft said +1.125 / −1.5, plan review P7). Scaled so the larger peak is +4 dBFS, the smaller is −2.0 dBFS, below the knee: steady gain −2.96 dB when the larger peak is on the sensed (positive) polarity and 0.00 dB when it is not, a **3.0 dB** difference, the ceiling margin. Spec FR-007: **3 ± 0.5 dB** (recorded in the spec's plan-review Clarifications).
  - **Bandwidth test** (FR-007, plan review P11): a 6 kHz tone at +6 dBFS plus a 1 kHz probe at −20 dBFS has a sum peak of +6.41 dBFS; against the +1.00 dBFS ceiling the expected probe drop is 5.41 dB; simulated −5.39 dB at 48 kHz. Spec: 5 ± 1 dB.
  - **Clipped onset duty** (FR-008): for a +11 dBFS onset after the limiter, 79 % of the samples in the first 2 ms are at or beyond ±1.0 (a 3.55 FS sine has 82 %), and 29 % after 20 ms (the 1.122 FS ceiling). The record filter reshapes this somewhat; the spec's 60 % / 40 % bounds leave the margin.
- **Rust figures (T011, 2026-10-11)**: the core unit tests pin every figure above and all matched within their tolerances at 6 and 48 kHz: dead time 14 / 152 samples, the +3 dBFS step 74 / 781, armed 2 / 12, release 1.362 s with −6.13 / −2.87 dB at 0.3 / 0.75 s, the +18 dBFS case 1.69 s, the release setting 0.198 / 3.982 / 9.957 s, the knee-aware mapping 3.0 ± 0.3 ms at knees −10 / −25 / −40 / +3 dBFS, attack 1 / 10 / 50 ms → 1.15 / 10.25 / 52.2 ms, polarity −2.96 dB vs bit-exact, unity 18.2 s after a burst, flush within 140 s, the 40 dB limit at +60 dBFS. One figure differs in detail: the **static ceiling** reads +1.003 dBFS at +2 dBFS and +1.03 (6 kHz) / +1.06 (48 kHz) at +20 dBFS against the reference's +1.00 … +1.04. The cap pins the peak sample to the detector onset and the capacitor then discharges for one cycle before the next peak, a sawtooth that grows with the level because Q5's base current grows with `vc` (the 192 kHz reference charges without the cap and sits slightly deeper). Well inside FR-004's ±0.5 dB; the unit test pins −0.01 … +0.07 dB around +1.00. The knee bisection reads +2.02 at both rates.
- **Rationale**: Principle II: the numbers must be reproducible from the repo; the reviewer's scratch simulation is not committed.
- **Alternatives**: citing the reviewer's figures without a script (rejected); a Rust-only derivation (the Rust model is the implementation under test, so an independent reference is needed).

## R-05 Settings mapping (FR-010, FR-011)

| Setting | Model parameter | Mapping | Default → parameter |
|---|---|---|---|
| `knee_dbfs` | detector threshold `VBE6` | `VBE6 = KDIV · V_FS · 10^(knee / 20)` (the conduction onset) | +1.0 dBFS → 0.602 V (0.6 V nominal, A-028) |
| `attack_ms` (dead time at 10 dB over the knee) | detector current gain `BETA6` | **knee-aware** (plan review, Q2): `BETA6 = 300 · (T_REF / attack_ms) · I(+1 dBFS) / I(knee)`, with `T_REF` = 2.17 ms (R-04) and `I(knee)` the detector's mean overdrive over one cycle of a 1 kHz sine at knee + 10 dB: `I = mean over θ of max(0, KDIV · clamp(V_FS · 10^((knee+10)/20) · sin θ, ±V_RAIL) − VBE6(knee))`, a fixed 360-point sum (θ at the bin centres) computed once at construction with detmath (`I(+1)` = 0.1174 V; `I(−10)` = 0.0947; `I(−40)` = 0.0030; `I(+3)` = 0.0626). Without the `I` ratio the dead time at low knees would be 10–100 ms and fail FR-011; with it the realized dead time at the 3 ms default is 2.3–3.3 ms at every knee from −40 to +3 dBFS (R-03 table) | 3.0 ms, knee +1 → 217 |
| `release_ms` (to −1 dB from 10 dB) | discharge scale `k_dis` on both discharge terms | `k_dis = 1370 / release_ms` (release ∝ 1/discharge current; realized / setting = 0.99–1.00 over the range, R-04) | 1370 ms → 1.0 (R11 = 10 MΩ exactly; plan review Q3) |
| `enabled` | — | skip the stage | on (A-020) |

- Ranges: knee **−40 … +3 dBFS** (below −40 the ceiling is near the VAS threshold; above about +4.7 dBFS the detector can never conduct because the rail `V_RAIL` = 1.2 V bounds its overdrive, so the cap is +3 with the knee's ±2 dB tolerance inside the usable range; plan review Q1), attack **1 … 50 ms** (the R12 charge-current limit, 390 Ω into 1 µF with conduction only near the peaks, floors the dead time near 1.1 ms at 48 kHz, so a 0.5 ms setting cannot be realized within FR-011's ±0.5 ms; found when the script was re-run after the plan review, recorded in the spec's plan-review Clarifications), release 200 … 10 000 ms. Validation as spec 002 FR-011 (finite, in range, named setting). `BETA6` is clamped to [10, 10 000] after the mapping as a guard; no setting in range reaches the clamp.
- The arming memory scales with `release_ms` (both discharge terms share `k_dis`), as FR-011 asks. The attenuation limit of 40 dB is a clamp on `vc` (the voltage giving −40 dB, derived at construction).
- **Alternatives**: calibrating `BETA6` by simulating the step at construction (deterministic but complex; rejected: the 360-point overdrive sum captures the knee dependence to within the FR-011 tolerance); a knee-independent mapping (rejected: 10–100 ms dead times at low knees); expressing the attack as a charge rate (rejected: Clarifications).

## R-06 ADC full-scale clamp (FR-008; spec Clarifications)

- **Decision**: `stages/clamp.rs`, a stage with `process(d) = d.clamp(-1.0, 1.0)` when enabled (bit-exact pass-through when bypassed; `f64::clamp` is a basic operation and NaN never reaches it, spec 001 Edge Cases). It runs in `DeviceChain` after the record stage and before the VAS, under `Settings::adc_clamp_enabled` (default true). `bypass_all` and the spec 001 configurations: `bypass_all` sets it false; every other configuration leaves it true.
- **Golden-v1 verification (2026-10-11)**: from the committed `RECORD_SOS`, the record stage's impulse response peaks at 0.570 at the identity rate and its in-band gain is ≤ 1.0000036, so none of the spec 001 golden stimuli (impulse 1.0, tone −20 dBFS, sweep 0.25, noise ±0.5) exceeds 1.0 after stage 4 at any host rate (the decimator attenuates the impulse further). `golden-v1.json` stays byte-identical with the clamp on (FR-016); the SHA guard proves it.
- **Measurement**: max |y| of a +10 dBFS tone through `record_only` at 6 kHz equals 1.0 exactly; the first 3 ms of a +10 dBFS onset through the default pipeline contain samples at ±1.0; with `adc_clamp_enabled = false` the same tone's peak exceeds 1.0.
- **Not modeled**: the codec input amp's rail clip before the filter (about +4.7 dBFS, the `V_RAIL` estimate) in the signal path; it is used only in the detector's view (R-02). Documented in R-14.
- **Implementation (T012, T016, 2026-10-11)**: `golden-v1.json` is unchanged as predicted (the SHA guard passed with the clamp on). Two spec 001 harness checks that feed input *beyond* full scale through the `default` configuration met the clamp: 001's Edge Case "over full scale is not clipped" now holds with the clamp off and is asserted both ways (clamped peak 1.0–1.5), and `us2_bypass_tap`'s own `bypass_all` helper sets the clamp off (R-06 above: `bypass_all` is the one 001 configuration with the clamp off). Neither was in the T016 expected-red list; they are restatements of a 001 check, not a behavior question. Also found: the **playback band-limit stage reconstructs a flat-topped waveform with overshoot** (the fundamental of a full-scale square wave is 4/π = 1.27), so the **default output can exceed ±1.0 on clipped audio** (1.38 for the +11 dBFS onset at 48 kHz) even though the record-path taps never do. The pipeline rustdoc says so; the CHANGELOG (T043) and README (T040) must too.

## R-07 VAS threshold re-anchored (FR-012; A-022 revised; 003 R-03 revised)

- **Decision**: `VasSettings::DEVICE.threshold_dbfs = -40.0`; the 3 dB per step, hang, onset and all VAS logic unchanged. Harness: `BURST_ABOVE_DB` stays 10, so the burst-gap stimuli are at −30 dBFS; the VAS golden stimuli follow (R-10). `vas_checks::input_referred_threshold_dbfs` becomes the identity below the knee (the limiter's static curve is unity there), and the interplay report's text and floor sweep are rewritten: floors −70 … −35 dBFS RMS in 5 dB steps through the default pipeline at level 3, reporting how much of each gap is kept.
- **Chain scenarios** (FR-012; a new `tests/chain.rs`): (i) the speech-like pattern (three groups of four 300 ms bursts at −30 dBFS peak, 150 ms apart, 5 s gaps; the 003 interplay stimulus re-leveled) over a −60 dBFS RMS floor at level 3: no splice inside a group (events' positions outside the groups), each 5 s gap cut to the hang time ± 1 ms; (ii) over a −45 dBFS floor: no event at level 3; at level 1 (threshold −34 dBFS) the gaps pause (noise peaks ≈ −36.5 dBFS, 003 R-03's 8.5 dB peak factor); (iii) 30 s of a −60 dBFS floor then a +6 dBFS burst of 1 s: one event, resume after the onset, the burst's samples at the ceiling after the dead time (measured at the "after record" tap with the clamp: peak exactly 1.0).
- **Rationale**: spec Clarifications; A-029's level scale.
- **Alternatives**: 6 dB per step (recorded, not adopted).
- **Implementation (T025–T029, 2026-10-11)**: all three scenarios pass at 6 and 48 kHz; the −45 dBFS floor never pauses at level 3 and pauses every gap at level 1 (removed lengths within 0.7 ms of gap − hang + onset), as P13 predicted. The interplay sweep shows the gaps kept at 20 % (the 1 s hang) from −70 to −50 dBFS and in full from −45 dBFS up. One measurement finding: **a stream that starts in silence pauses H device samples after the stream start**, which at a converting rate is the host-to-device conversion delay (half the bypass latency, 001 R-10; 4.75–5.2 ms, 0 at 6 kHz) *before* the corresponding input time, because the converter's empty history counts as silence; the resume is referenced to the burst through that same delay, so scenario (iii)'s removed length carries one conversion delay, which the check accounts for (the ±1 ms is unchanged). Scenario (i) never sees it: its first pause follows sound. The spec 003 harness never started a stream with more than a hang time of silence, so this is the start-of-stream counterpart of 003 R-11's end-of-stream trap. Cheap to run: the 30 s scenario takes 0.5 s in debug.

## R-08 Measurement methods (FR-018; retiring 002 R-11)

- **Exact gain at the tap**: the `agc_only` configuration is `Tap::AfterAgc` with stages, clamp and VAS off; `y[n] / x[n]` where `|x[n]| ≥ 0.1 · A` (002 R-15's gate) at every host rate, no reference run, no boundary. `agc_checks::measure_timing` and the reference-ratio method are deleted; `check_ratio_self_test` is deleted.
- **Checks** (each a `MeasurementResult` with trace IDs):
  - `check_fr003_passthrough(rate)`: 1 kHz at −20 dBFS, speech-like bursts at −30, noise ±0.5, and a 5 s tone at knee − 1.5 dB: output bit-identical to input (differing samples == 0).
  - `check_fr004_static(rate)`: the static-curve set (−60 … +20 dBFS in 2 dB steps, 1 dB from −4 to +6), 5 s tones at the aligned phase, last second: output peak vs ceiling ±0.5 dB above knee + 1.5 dB; report rows within ±1.5 dB; `knee_bisection` to 0.1 dB: +2 ± 2 dBFS.
  - `check_fr005_attack(rate)`: step −20 → +11 dBFS (10 dB over the knee) after 20 s (the 20 s at −20 dBFS is replaced by a fresh pipeline, which is the same state by R-03): **dead time = time of the first sample whose attenuation exceeds half the steady attenuation** (the steady value is the mean gain over the last 50 ms of the step; the same relative rule for every step size, plan review P1), 3 ± 1.5 ms; ramp from that sample to within 1 dB of the steady value ≤ 1 ms; max over-attenuation vs the steady value ≤ 1 dB; the step to **+3 dBFS** (2 dB over the knee, whose steady attenuation is 2 dB) has a dead time ≥ 3× the +11 dBFS value (model 5.2×, about 16 ms); armed: +11 dBFS burst 0.2 s, −20 dBFS 2 s, +11 dBFS: dead time ≤ 0.5 ms.

## R-14 Known deviations not modeled (FR-007, FR-019)

The detector's 13 kHz roll-off (C10/R15) and 7 Hz DC block (C5/23 kΩ): the emulator's detector sees the host input's full band and any DC offset. The codec input amp's rail clip in the signal path (about +4.7 dBFS): only its effect on the detector is modeled; the signal path is clamped at full scale after the filter instead. The knee's temperature drift (−0.3 dB per 10 °C). The mic amp's own clipping 7–16 dB above the knee (stage 2, out of scope). The transistor parameters are estimates: the dead time is uncertain by about 3× either way, the release by about 40 %, the knee by ±2 dB. Captures that settle them are listed in FR-019 and the issue template. One datasheet lead bounds the dead time without a unit: the MSM7702's AIN+ reference output impedance (S-003 pages 4–17, unread) is the source impedance of the detector's emitter and sets its peak charge current together with R12; `docs/hardware/sources.md` lists it.

## R-15 Risks

- **The spec's figures are the model's**: if the Rust implementation and the reference script disagree beyond the tolerances, the plan is wrong, not the spec; stop and re-derive (the pinning unit test).
- **6 kHz grid**: the dead time is quantized to about ±0.17 ms and phase-dependent; the FR-005 tolerance (±1.5 ms) covers it with aligned-phase tones; arbitrary-phase input at the identity rate is a documented model property.
- **Chain scenario (ii)**: the −45 dBFS RMS floor's peaks (about −36.5 dBFS, 003 R-03's 8.5 dB peak factor) sit about 2.5 dB **below** the level-1 threshold (−34 dBFS) and 3.5 dB above the level-3 threshold (−40 dBFS), so level 1 pauses the gaps and level 3 does not. Verified with the harness's band-limited noise generator at plan review (P13): at level 3 the longest sub-threshold run is 0.36–0.60 s, under the 1 s hang, so it never pauses; at level 1 the floor never crosses. No re-leveling fallback is needed (the plan's first draft had the sign reversed).
- **VAS mute-mode and the clamp**: a muted region's ring-out passes through the clamp unchanged (it never exceeds 1.0); no interaction expected.
- **C callers of 0.4**: a 72-byte struct is rejected; the renamed field fails to compile. Both intended; recorded.
- **Attack range floor**: the realized dead time cannot go below about 1.1 ms at 48 kHz (R-05), so the range starts at 1 ms; if the implementation's 1 ms case lands outside 1 ± 0.5 ms at some rate, raise the minimum rather than widen the tolerance.
