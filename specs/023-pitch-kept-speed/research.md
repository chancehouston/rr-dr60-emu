# Research: Pitch-Kept Playback Speed (spec 023)

**Date**: 2026-10-31 | **Spec**: [spec.md](spec.md) (D1 – D11 approved; D12 from the plan reviews) | **Baseline**: 0.22.0, merge commit 12a3c45 | **Plan reviews applied**: coach 1 – 16, hardware B1 – B8, product M1 – M9 (2026-10-31; the hardware reviewer's simulation `scratchpad/wsola_plan.py` implements the plan's rules line for line and is the seed of the design script)

Every item: Decision, Rationale, Alternatives. Code references are to the tree at 12a3c45.

## R-01 Where the time-scaler lives

**Decision**: inside `stages/speed.rs`'s `SpeedStage`, beside the resampler, as a fixed-size `TimeScaler` struct (no heap of its own; the window table a `Box<[f64]>` of 120 built at construction with `detmath::cos`, shared): fields `origin: u64` (the device output index the frame grid is anchored at), `n: u32` (the output's index inside the current synthesis hop, 0 … 59), `cur_a: i64`, `cur_s: i32` (the current frame's nominal analysis position, a whole stored sample, and its chosen shift), `prev_a`, `prev_s` (the previous frame's). The stage keeps `mode: Mode` and `requested_mode: Mode` beside `active`/`requested`, and the place arithmetic (`p5`, `step`, `latch`, the deferred switch into level 3, `final_count`) is untouched (D4). **The pulls are lazy** (hardware B4): the search pulls through `cur_a + Δ + Lc − 1` (+99) at the hop boundary and the synthesis pulls `max(j_prev, j_cur)` per output; an eager `+ N + Δ` pull overruns the 256-sample ring in the 5 → 1, 4 → 1 and 5 → 2 mode blends with a simultaneous level change (spans 284 / 260 / 260); lazy, the worst span over all 40 level pairs × 60 phases is **224** (5 → 1, scaler → resampler), everything else ≤ 200, so `RING` stays 256 and a sweep test (`ring_span_pitch_within_256`: the 40 cells × 60 phases with a simultaneous level change, debug build) pins it. The window table is **generated** (`speed_window.rs`, `from_bits` as `output_coeffs.rs`): w[0 … 59] from the script's cosine and **w[60 + n] := 1 − w[n]** exactly, so the sum is exactly 1.0 at every n (through `detmath::cos` it is off by up to 3 ULP at 19 entries and w[30] is not 0.5: hardware B1); the pin is the exact sum and w[30]'s bits.

**Rationale**: the place is the clock in both modes (D4) and the transport's pull model, the latch and spec 020's walker read it; one stage, two mechanisms behind one `next()`. The steady identity fast path at level 3 is untouched (the mode test sits after its conditions: `fade.is_none()` already excludes a blend; `mode` is read only in `next_general`).

**Alternatives**: a separate stage after the resampler (two places to keep in step); a decoder-domain method (the codec is a class match).

**Restated at implementation (2026-10-31)**: the lazy pulls read the candidates' span *and the continuation*: at a hop boundary the stage pulls through max(cur_a + Δ + Lc − 1, cont + Lc − 1) with cont = prev_a + prev_s + Ss. On the slow levels the continuation lies past the span (at level 1, cont = cur_a + 24 + prev_s, so cont + 59 reaches cur_a + 123 against the span's cur_a + 99); the first draft pulled the span only and correlated the continuation's end against zeros, which the square-wave pin could not see (its periodic candidates tie) and the vowel did (the harness reference, which reads the whole stored stream, disagreed at the tenth hop). The ring still holds (the stationary span 164 by the script; the mode-blend worst case under 256 by the 40-pair × 60-phase unit test with the debug assertion on). A frozen old scaler of a blend continues its hops but records no shift (the trace is the live branch's).

## R-02 The synthesis

**Decision**: output o inside hop k (n = 0 … 59): `y = x[prev_a + prev_s + Ss + n] · w[Ss + n] + x[cur_a + cur_s + n] · w[n]`, both reads through `x()` (zeros outside [0, K)), w the periodic Hann of length N = 120 (`w[n] = 0.5 − 0.5·cos(2πn/N)`, so `w[n] + w[n + 60] = 1` within 2 ULP, pinned; `w[30]` pinned to the detmath value). At the hop boundary (n = 60) the frame advances: `prev ← cur`, `cur_a ← place at this output` (⌊p5 ÷ 5⌋, whole by construction since every hop is a multiple of 5 fifths: hardware B3), `cur_s ← the search`. The anchor: at the first output the scaler computes after leaving level 3 or at a mode change, `origin = o`, `prev_a = a₀ − Ss`, `prev_s = 0`, `cur_a = a₀`, `cur_s = 0` (the first frame has no continuation to match), so outputs 0 … 59 are `x[a₀ + n]·(w[60 + n] + w[n]) = x[a₀ + n]`: a full-gain onset (hardware B4c), no fade-in. **Bit-exact by a shortcut**: whenever `prev_a + prev_s + Ss == cur_a + cur_s` (an exact continuation: the anchor hop and every hop whose search picked the continuation) the output is `x[cur_a + cur_s + n]` itself (one compare per output), since two roundings of a complementary pair are not the identity in 5 % of cases (hardware B1); the onset oracle is then bit-exact against level 3. The hop's nominal `cur_a` is ⌊p5 ÷ 5⌋ (whole only until a mid-hop level change; the < 1-sample residue lies inside the search).

**Rationale**: one multiply-add pair per output plus the search once per hop; continuity at a ratio change is by construction (the previous frame's position is the actual one, not the nominal); the level-3 twin at the onset is exact on the first hop.

## R-03 The search

**Decision**: at each hop boundary, over shifts s in the outward order 0, −1, +1, −2, +2, … , −Δ, +Δ (Δ = 40), the plain cross-correlation `c(s) = Σ_{n<Lc} x[cur_a + s + n] · x[prev_a + prev_s + Ss + n]` (Lc = 60: the overlap region), summed as four partial sums in a fixed order (the `dot` pattern of 013 R-03), the shift with the strictly largest c (a tie keeps the earlier candidate, so the smaller displacement; silence gives 0). 81 candidates × 60 = 4860 multiply-adds per hop, once per 60 outputs: 81 per output on average (plus 2 for the synthesis), against the resampler's 57. **Measured** (hardware B7, release, this machine): through the masked ring reads a hop's search is 1866 ns (31 ns per output, 1.9 × the resampler's 16.7 ns); **copying the 140 + 60 samples into two contiguous f64 buffers first** (reserved at construction) and running the 81 dots on slices in the same summation order is 363 ns per hop (6 ns per output, 0.36 ×): the plan takes the copied form, so the 3 × budget holds with margin on the x86 runner too. The pulls: lazy (R-01). A frame whose nominal position is at or past K still searches (its reads are zeros past K); the tail proof (R-06) does not need a special rule. Normalized correlation was tried in the simulation and declined (2 × the search for 0.8 dB less onset bias; the plain form lifts quiet syllable onsets by up to +2.3 dB at level 1, recorded).

**Rationale**: hardware B3 (Δ ≥ P_max/2 for 75 Hz), B7 (determinism: no normalization, no `sqrt`, a fixed order, an outward tie-break).

**Alternatives**: normalized correlation (a division and a `sqrt` per candidate); Δ = 60 (2.2 ×); a fractional refinement (out of scope).

## R-04 The level change and the frame grid (D5)

**Decision**: the request lands in the place at d(P) exactly as today (`apply_request` changes `active`); in pitch-kept mode a change between levels 1, 2, 4, 5 starts **no** crossfade; the next hop boundary reads the new ratio through `cur_a = place` (continuous: the simulation reads the change window within ±0.12 dB of the held window on tones and +0.18 dB on voice, hardware B3a). The grid is anchored at `origin` and advances by Ss outputs per hop regardless of the host's blocks (partition-independent). **A change into level 3 (D12, replacing the plan's first rule)**: the deferred switch keeps 013's wait for a whole place, then a **20 ms smoothstep fade from the frozen scaler to the identity** (R-05's `Fade` with the old branch the scaler's copy continuing its own hops and the new branch `x[i]`); the plan's first rule (the current frame's remaining overlap onto the identity) swaps the dominant branch at a weight near 1 and reads **13 dB worse than an instant step** at a late landing in the hop (hardware B3b: −18 … +16 dB against a held floor of −32 … −41 dB), while the fade reads at the floor on every row (38 – 52 dB below the step). If K is reached during the fade the drain cuts it (019 D6's rule, documented). A change out of level 3 anchors a new grid at d(P) with no wait (x[i − 1] then x[a₀ = i] at full gain: continuous).

**Oracle** (coach 5): reading A = 019's 40 ms reader on the residual (the changed run minus the held-level run) centred on the first hop boundary after d(P), the tone excluded; reading B = the same reader on the same residual 200 ms later; assert A ≤ B + 1 dB on the tone rows (the `restart_overlap` mutant, the previous frame dropped at the change, reads +40 … +55 dB there; on voice +0.96 dB at most, so the voice row is reported); the design script prints A, B and the mutant's A for every asserted row before the implementation; the into-3 fade is asserted by the click table of R-05 with the `into3_swap` mutant (the plan's first rule).

## R-05 The mode change (D5)

**Decision**: a `Fade` whose old branch is the old mechanism frozen at its level: `Fade { old_k, old_p5, n, old_mode, old_scaler: TimeScaler }` (a copy of the scaler state when the old mode is pitch kept; a fixed-size struct, no allocation); the new branch starts at the common place: pitch kept → the scaler anchored at d(P) with shift 0; the default → the resampler at the place. The blend `y_old + w·(y_new − y_old)` over 120 outputs as spec 019. At level 3 (both branches the identity) the mode applies at once with no fade and logs its entry. The one wait rule: `apply_request` and `apply_mode_request` both return while `fade.is_some()`; the latest request per control waits; past the latch both are dropped (logged by the stream state as 019 D4). The pulls follow the leading branch (the larger of the two branches' lazy reads; the frozen scaler and a new scaler never coexist, so at most one search per output). The anchor at a mode change from the default mode takes ⌊p5 ÷ 5⌋ (a fractional place floors; the residue is inside the ambiguity below).

**Oracle** (coach 6): 019's click reader with both tones (f·r and f) excluded, the baseline the instant-switch mutant `mode_step`; **the 30 dB rows asserted on the 1 kHz tone** (the scaler's own spurious is at the floor there; on the off-grid tone the scaler's 28 – 36 dB spurious is the floor, so those rows are reported with the floor printed, as 019 did); the voiced figure reported. **The content offset** (coach 3): within a hop the audio heard at output n is x[cur_a + s + n] while the place is cur_a + n·r, so the offset is s + n·(1 − r): at most Δ + 59·|1 − r| = **64 device samples (10.7 ms)** at levels 1 and 5, 52 at levels 2 and 4; at a mode blend's end ≤ Δ without a level change, ≤ Δ + 96 with a simultaneous 5 → 1; pinned in `pitch_matrix` from the shift and place traces (max |content − place| over a run), published in the guide and the spec (a dated restatement of the draft's "±Δ").

## R-06 The length (D4)

**Decision**: the latch is 013's (the place reaches K). In pitch-kept mode the remaining outputs after the latch are counted from the hop grid: the current hop m (its start o_m = origin + Ss·⌊(own − origin) ÷ Ss⌋) continues to its end, the next hop's frame has a nominal position ≥ K, so the content ends when the previous frame's tail has faded through that hop: `T_c = 120 − ((own − origin) mod 60)`, or 60 when the remainder is 0, so **T_c ∈ [60, 119], at most 120** (the spec's 160 restated). **The proof needs Δ < Ss** (hardware B5): a frame past K can take a negative shift and pull up to Δ = 40 samples of content before K into its **first half only** (its second half starts at a + s + 60 ≥ K + 20), so content never reaches the hop after; the simulation found no exceedance in 1500 random (K, level, signal) trials with the search allowed past K, and the registered alternative Δ = 60 would break the proof (recorded beside it). T_c is a grid bound, not a content bound (at K = 59, level 2, the 106-sample tail has no non-zero output): the guide says "at most". The length test runs with the tail rule removed (013's `no_tail` pattern) and asserts the output from `final_count` on is exactly 0 at seven rates and the four levels for K ∈ {1, 59, 119, 600}. `playback_length_samples_in_mode(number, level, mode)`: pitch kept at level 3 → the default's figure (the identity); else `own = ⌈5K ÷ k⌉`, `T_c` from `origin = 0` (a playback from the start at a constant level): `o_m = 60·⌊own ÷ 60⌋`, `T_c = 120 − (own − o_m)` when own mod 60 ≠ 0, else 60; total `⌈(own + T_c)·m ÷ l⌉ + drain`. `finished` arrives on it (asserted at seven rates). K = 1, 59, 119: own 2 / 99 / 199 at level 1, T_c 118 / 81 / 101; asserted.

**Rationale**: the house standard since 013 is exact (coach 4, hardware B4).
