# Tasks: 6 kHz Device Rate and Codec Filter Templates

**Input**: Design documents from `specs/004-device-rate-6khz/`: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md)

**Tests**: REQUIRED. Constitution III says measurement tests are written first and must fail before the implementation exists. Every phase lists its tests before its implementation tasks. For this feature "fail first" has a specific shape: the restated checks are written against the new templates and the 6 kHz rate, so they fail against the 8 kHz code; then the core flips and they pass.

**Organization**: Setup → Foundational (the core flips to 6 kHz: constants, rate table, boundary, two coefficient sets, stage generics, core unit tests; harness compiles) → US1 (P1, MVP: the two stage templates measured by the harness) → US2 (P2: host rates, the identity rate, the boundary, latency, C parity) → US3 (P3: AGC and VAS restatements, the single golden re-bless, CHANGELOG, register, sources, earlier-spec pointers) → CI → Polish.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: The user story the task belongs to (US1, US2, US3)
- Paths are relative to the repository root.

## Conventions that apply to every task

- **Traceability**:
  - Cite spec 004 FR, SC and A-/S-IDs in code comments, rustdoc and test names, e.g. `// A-026: 6 kHz device rate`, `// A-027: transmit template scaled by 0.75`, `// S-005 300 Hz row`.
  - Design and harness constants that are not device properties are commented `// engineering target (004 FR-015)` or `// engineering target (004 R-xx)`; the list is research R-14.
  - Restated figures cite the spec they come from and this one, e.g. `// 002 FR-008 tones, restated by 004 FR-011`.
  - Harness results cite requirements as `004/FR-0xx`; AGC and VAS results keep `002/FR-0xx` and `003/FR-0xx`.
- **Determinism**: in `rr_dr60`, only basic IEEE operations and integer arithmetic, plus `rr_dr60_detmath` at construction. No platform libm (`clippy.toml` enforces this). Coefficients are committed bit patterns generated by the Python tools; the Rust build never runs Python.
- **Real-time safety**: no new allocation, formatting or I/O in any processing path. The stage types stay fixed-size arrays (research R-06).
- **The golden window**: from the core flip (T009) until the re-bless (T038), the three golden tests, the two SHA guards and the mutation golden checks are **expected red**, and so is every harness test whose figures have not yet been restated. Before ticking a task in that window, this must pass instead of the full suite: `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test -p rr_dr60 -p rr_dr60_detmath -p rr_dr60_ffi --all-features`, and every harness test binary the task touches. Each checkpoint names what is expected red. From T038 on, `cargo test --all-features` must be fully green before ticking anything.
- **One re-bless**: `RR_DR60_BLESS=…` is run exactly once in this feature, in T038, together with the CHANGELOG entry (FR-013). Any later golden difference is a defect.
- **Never widen a spec tolerance** to make a test pass. Raise it with the user instead. The design-time trade-off rule lives in research R-04 (edge search); the harness tolerances are the datasheet limits.
- **Story boundaries (Principle VII)**: `us1_voiceband.rs` and `us2_bypass_tap.rs` (US1) and `edge_cases.rs`, `latency.rs` (US2) use plain assertions or the 001-style check functions in `checks.rs`; the AGC and VAS checks (US3) keep their isolated configurations.
- **Before ticking a task** (outside the golden window): `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -- -D warnings` and `cargo test --all-features` must pass.
- **Commits**: Conventional Commits, on branch `004-device-rate-6khz`. The re-bless commit (T037 + T038) is `feat!:` (breaking: all output and the rate list). Merge to `main` only through a green PR, and only after the user says so.
