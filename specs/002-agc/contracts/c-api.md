# Contract: C API changes (`rr_dr60.h` 0.1.0 → 0.2.0)

This is a delta against [001's C API contract](../../001-pipeline-skeleton/contracts/c-api.md). Contract rules 1–4 are unchanged. Rule 5 is refined below. The header is still generated by cbindgen and committed, and CI checks it for drift.

## Functions

- `rr_dr60_settings_default(rate)`: also fills the AGC fields with the device defaults. `struct_size = 48`.
- **NEW** `RrDr60Status rr_dr60_settings_validate(const RrDr60Settings *settings, RrDr60SettingField *out_field)`:
  - **Return value**: exactly the status `rr_dr60_create` would return for these settings. If `out_field` is not NULL, the function also writes the offending field there (`NONE` when the status is OK).
  - **Order**: struct size → tap → host rate → AGC fields in struct order, the same order `create` uses.
  - **NULL**: a NULL `settings` returns `RR_DR60_STATUS_NULL_POINTER`. `out_field` may be NULL.
  - **Guarantees**: never allocates, real-time safe, panic-guarded.
- `rr_dr60_create`, `rr_dr60_reconfigure`: use the same validator. They return `RR_DR60_STATUS_INVALID_SETTING` for an out-of-range or non-finite AGC field. `reconfigure` leaves the pipeline unchanged on any error (contract rule 2).

## Rule 5: struct growth (unchanged)

- `struct_size` must be ≥ `sizeof(RrDr60Settings)` of the library version in use (48 for 0.2). A smaller value, including the 0.1 layout's 24, returns `RR_DR60_STATUS_INVALID_ARGUMENT`, and `rr_dr60_settings_validate` names `RR_DR60_SETTING_FIELD_STRUCT_SIZE`.
- 0.1 was never released, so no caller needs the old layout. Accepting it would require raw, partial reads of the struct (research.md R-09).
- Callers start from `rr_dr60_settings_default()` and change only the fields they need.
- The Rust-side `RrDr60Settings` derives `Clone, Copy, Debug, PartialEq`. `Eq` is dropped because of the float fields.

## Parity

The output of the C API matches the Rust API bit for bit for the same settings, including non-default AGC values and every tap value (FR-014). The FFI parity and allocation tests map taps with an exhaustive match, so `AfterAgc` is tested as itself (research.md R-10). They cover the default, `agc_only`, `agc_tap_stages_on` and each extreme setting.
